训练开销Training cost

训练时间比较使用同一台服务器上四组已保存的训练记录。各组均使用 4 张 RTX 4090 D、FSDP2、有效 batch 32，并完成 10,000 次参数更新。数据集、相机与执行配置不同，因此比较对象是这些具体训练方案。

Training cost is compared across four archived runs on the same server. Each uses four RTX 4090 D GPUs, FSDP2, an effective batch of 32, and 10,000 parameter updates. Datasets, cameras, and execution settings differ, so the comparison concerns these specific training configurations.

更新耗时Time per update

统计第 500–10,000 步的 update_s，每组包含 9501 次更新。该计时覆盖批内预处理、前向、反向、通信和优化器更新；读数据等待、验证、保存及启动开销另计。恢复训练按实际继承的步数拼接，舍弃被回退覆盖的重复步。

The comparison uses update_s from steps 500–10,000: 9,501 updates per run. This timer covers batch processing, forward and backward passes, communication, and optimizer updates. Data waiting, validation, saving, and startup are separate. Resumed runs are assembled along the actual checkpoint lineage, excluding rolled-back updates.

在四卡、有效 batch 32 的条件下，本组 OpenWAM 的更新耗时中位数为 15.74 s，低于四相机 π0.5 的 32.12 s 和三相机 π0.5 的 24.43 s，单步耗时分别减少 51.0% 和 35.6%。这一结果说明，OpenWAM 在本组输入与执行配置下具有更低的参数更新成本。各组每次更新都处理 32 个样本，示教总数不同不会直接改变每次更新的计算批量。

With four GPUs and an effective batch of 32, this OpenWAM configuration has a median update time of 15.74 s, versus 32.12 s for four-camera π0.5 and 24.43 s for three-camera π0.5: reductions of 51.0% and 35.6%. The result establishes a lower parameter-update cost for this OpenWAM input and execution configuration. All runs process 32 samples per update; differing demonstration counts do not directly change that computational batch size.

这个差距需要结合实际计算路径理解：OpenWAM 的视频经过 VAE 压缩，再由视频与动作 DiT 训练；每卡 8 个样本一次完成前后向。两组主要 π0.5 对照训练视觉、语言与动作分支，每卡 batch 2、累积 4 次，且进入联合注意力的序列更长。OpenWAM 虽有更多可训练参数，但每个参数参与的序列长度、计算次数与通信组织不同。下文分别核对这些配置；已有记录没有单独测出各因素贡献的加速比例。

The gap must be interpreted through the computation performed. OpenWAM compresses video through the VAE and trains the video and action DiTs, processing eight samples per GPU in one forward/backward pass. The two main π0.5 comparisons train vision, language, and action branches with batch 2 per GPU, four accumulation passes, and longer joint-attention sequences. OpenWAM has more trainable parameters, but sequence lengths, repeated operations, and communication organization differ. The following sections examine these settings; the archived runs do not isolate each factor's share of the speed difference.

另一组三相机 π0.5 在每卡 batch 4、累积 2、开启重计算的配置下达到 13.14 s，比本组 OpenWAM 更短。因此，这里的速度排序适用于所列训练方案，不能推广为 WAM 架构普遍更快。它也没有衡量两种模型达到相同任务成功率分别需要多少训练时间；后者还需要同任务、同评估标准的训练预算对照。

Another three-camera π0.5 configuration reaches 13.14 s with batch 4 per GPU, two accumulation passes, and checkpointing enabled, faster than this OpenWAM run. The ranking therefore applies to the listed training configurations rather than establishing a general WAM architecture advantage. These measurements also do not compare the training time required to reach equal task success; that requires a matched task, evaluation protocol, and training-budget comparison.

累计更新耗时也不等于完整训练周期。OpenWAM 从第 300 步恢复后的 9700 次更新累计约 43.72 h，包含验证与保存的训练循环进度条记录约 54.56 h，更新累计约占 80.1%。因此，更新阶段的耗时优势不能直接换算为整个实验周期的等比例缩短。

Accumulated update time is distinct from the full training cycle. The 9,700 OpenWAM updates after resuming from step 300 total about 43.72 h, while the training-loop progress timer, including validation and saving, records about 54.56 h: updates account for approximately 80.1% of this loop time. The update-time advantage therefore does not translate directly into a proportional reduction of the full experiment duration.

可训练参数Trainable parameters

参数量由训练日志与检查点张量形状交叉核对。OpenWAM 共 12.406B 参数，其中 6.021B 参与更新；π0.5 共 3.617B，其中 3.353B 参与更新。OpenWAM 的可训练参数约为 π0.5 的 1.80 倍，因此它在前两组对比中的速度优势需要从计算路径解释。

Training logs and checkpoint tensor shapes agree on the counts. OpenWAM stores 12.406B parameters, of which 6.021B are trainable; π0.5 stores 3.617B, with 3.353B trainable. OpenWAM has approximately 1.80× as many trainable parameters, so its speed advantage over the first two π0.5 configurations must be understood through the computation performed.

冻结的 VAE 与 T5 仍在 OpenWAM 每个训练批次中执行前向编码，但不计算它们的参数梯度，也不为这些参数维护 AdamW 更新状态。视频与动作 DiT 则共同训练。π0.5 的全参配置同时更新视觉、语言和动作分支；其输入 embedding、重复处理的视觉 token、内部线性层与冻结输出头承担的计算各不相同，简单相加参数量不能给出每步计算成本。

OpenWAM still runs its frozen VAE and T5 in each training batch, but does not compute their parameter gradients or maintain AdamW update states for them. Its video and action DiTs train jointly. Full π0.5 fine-tuning updates vision, language, and action branches. Input embeddings, repeatedly processed visual tokens, internal linear layers, and frozen output heads contribute differently to computation, so summing parameter counts does not determine update cost.

计算配置Compute configuration

首先是进入主干的序列长度。OpenWAM 将三路相机拼成 384×320 的画布，每个样本取 9 个时刻；VAE 在时间上压缩为 3 帧、空间上压缩为 24×20，再按 2×2 latent patch 展开为 360 个视频 token，与 32 个动作 token 交互。π0.5 将每路图像缩放并补边到 224×224，经 14×14 patch 得到每相机 256 个视觉 token：四相机加 200 个文本/状态位置与 50 个动作位置，共 1274 个位置；三相机为 1018 个。虽然网络层数、宽度与条件注意力路径也不同，VAE 对时空序列的压缩确实减少了 OpenWAM 主干需要反复处理的位置数。

First, the backbone sequence lengths differ. OpenWAM packs three cameras into a 384×320 canvas at nine time points. The VAE compresses this to three latent frames of 24×20; 2×2 latent patches produce 360 video tokens interacting with 32 action tokens. π0.5 resizes and pads each camera to 224×224, producing 256 visual tokens through 14×14 patches. Four cameras plus 200 text/state positions and 50 action positions give 1,274 positions; three cameras give 1,018. Layer counts, widths, and conditioning-attention paths also differ, but VAE compression reduces the positions repeatedly processed by the OpenWAM backbone.

其次是微批组织。两组主要 π0.5 对照都要执行 4 次微批前后向，才完成一次有效 batch 32 的更新；OpenWAM 一次处理每卡 8 个样本。当前 FSDP2 实现按模块收集和重新分片参数，微批次数会影响这些操作及梯度通信的执行频次。OpenWAM 开启梯度重计算，以额外前向计算换取激活显存，配合较大的微批；π0.5 的两组主要对照关闭了重计算。这个设置不能单独解释速度，但它改变了能容纳的 batch 与通信组织。[9]

Second, the main π0.5 comparisons perform four microbatch forward/backward passes per effective-batch-32 update, while OpenWAM processes eight samples per GPU in one pass. The FSDP2 implementation gathers and reshards parameters by module; microbatch count affects these operations and gradient-communication frequency. OpenWAM enables activation checkpointing, trading extra forward computation for activation memory alongside its larger microbatch. The two main π0.5 comparisons disable checkpointing. This setting changes feasible batch size and communication organization, but does not alone explain the timing difference. [9]

最后是实际数值类型与注意力实现。OpenWAM 检查点全部以 BF16 存储，并开启 BF16 autocast；π0.5 虽配置 mixed_precision=none，检查点仍有约 96.69% 参数以 BF16 存储，其余约 3.31% 为 FP32，不能按纯 FP32 训练解读。该版本 π0.5 的联合注意力显式计算注意力矩阵与 softmax，OpenWAM 的对应路径调用 PyTorch SDPA；是否采用某个融合内核仍由设备、形状和 mask 决定。这些实现差异与序列长度、微批组织共同作用，已有运行没有逐项隔离各因素的耗时贡献。[9]

Finally, actual dtypes and attention implementations matter. OpenWAM stores all checkpoint parameters in BF16 and enables BF16 autocast. Despite mixed_precision=none, π0.5 stores approximately 96.69% of checkpoint parameters in BF16 and 3.31% in FP32, so this is not pure-FP32 training. This π0.5 version explicitly computes the joint attention matrix and softmax; the corresponding OpenWAM path calls PyTorch SDPA. Fused-kernel selection depends on device, shapes, and masks. These implementation choices act together with sequence length and microbatch organization; the archived runs do not isolate each factor’s timing contribution. [9]

后续效率对照应固定数据与三路相机、有效 batch 和软件版本，分别改变每卡 batch/累积、重计算及注意力实现，同时记录更新耗时与峰值显存。跨模型仍需保留各自合理的输入表示，并把任务成功率与训练预算一起报告；相同步数只代表相同次数的优化器更新。

A subsequent efficiency comparison should fix data, three camera streams, effective batch, and software versions, then vary microbatch/accumulation, checkpointing, and attention implementation separately while recording update time and peak memory. Cross-model comparisons should retain suitable input representations and report task success alongside training budget; equal step counts mean equal numbers of optimizer updates.
