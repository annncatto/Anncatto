训练开销Training cost

训练时间比较使用同一台服务器上四组已保存的训练记录。各组均使用 4 张 RTX 4090 D、FSDP2、有效 batch 32，并完成 10,000 次参数更新。数据集、相机与执行配置不同，因此比较对象是这些具体训练方案。

Training cost is compared across four archived runs on the same server. Each uses four RTX 4090 D GPUs, FSDP2, an effective batch of 32, and 10,000 parameter updates. Datasets, cameras, and execution settings differ, so the comparison concerns these specific training configurations.

更新耗时Time per update

统计第 500–10,000 步的 update_s，每组包含 9501 次更新。该计时覆盖批内预处理、前向、反向、通信和优化器更新；读数据等待、验证、保存及启动开销另计。恢复训练按实际继承的步数拼接，舍弃被回退覆盖的重复步。

The comparison uses update_s from steps 500–10,000: 9,501 updates per run. This timer covers batch processing, forward and backward passes, communication, and optimizer updates. Data waiting, validation, saving, and startup are separate. Resumed runs are assembled along the actual checkpoint lineage, excluding rolled-back updates.

在四卡、有效 batch 32 的条件下，本组 OpenWAM 的更新耗时中位数为 15.74 s，低于四相机 π0.5 的 32.12 s 和三相机 π0.5 的 24.43 s，单步耗时分别减少 51.0% 和 35.6%。这一结果说明，OpenWAM 在本组输入与执行配置下具有更低的参数更新成本。各组每次更新均处理 32 个样本，计算差异主要体现在每个样本的输入形状、模型计算路径与批次执行方式上。

With four GPUs and an effective batch of 32, this OpenWAM configuration has a median update time of 15.74 s, versus 32.12 s for four-camera π0.5 and 24.43 s for three-camera π0.5: reductions of 51.0% and 35.6%. The result establishes a lower parameter-update cost for this OpenWAM input and execution configuration. All runs process 32 samples per update; the main computational differences lie in per-sample input shapes, model computation, and batch execution.

这个差距需要结合实际计算路径理解：OpenWAM 的视频经过 VAE 压缩，再由视频与动作 DiT 训练；每卡 8 个样本一次完成前后向。两组主要 π0.5 对照训练视觉、语言与动作分支，每卡 batch 2、累积 4 次，且进入联合注意力的序列更长。每次更新的开销由参与训练的模块、各模块处理的序列长度，以及计算与通信的执行次数共同决定。

The gap is best understood through the computation performed. OpenWAM compresses video through the VAE and trains the video and action DiTs, processing eight samples per GPU in one forward/backward pass. The two main π0.5 comparisons train vision, language, and action branches with batch 2 per GPU, four accumulation passes, and longer joint-attention sequences. Update cost depends jointly on the modules being trained, the sequence lengths they process, and how often computation and communication operations run.

另一组三相机 π0.5 在每卡 batch 4、累积 2、开启重计算的配置下达到 13.14 s，是四组记录中单步更新耗时最低的方案。两种模型的速度排序随所比较的训练方案而变化，因此训练吞吐的比较需要同时列明模型、输入与执行设置。

Another three-camera π0.5 configuration reaches 13.14 s with batch 4 per GPU, two accumulation passes, and checkpointing enabled—the lowest update time among these four runs. The relative speed of the two models varies with the training configurations being compared, so a throughput comparison should specify the model, inputs, and execution settings together.

完整训练周期还包括数据等待、验证和保存。OpenWAM 从第 300 步恢复后的 9700 次更新累计约 43.72 h，训练循环进度条记录约 54.56 h，更新累计约占 80.1%，其余环节约占 19.9%。单步耗时用于比较参数更新的吞吐，训练循环总时长则用于安排实验周期和 GPU 使用预算。

The full training cycle also includes data waiting, validation, and saving. The 9,700 OpenWAM updates after resuming from step 300 total about 43.72 h, while the training-loop progress timer records about 54.56 h. Updates account for approximately 80.1% of this loop time, with other stages accounting for 19.9%. Per-update time measures update throughput; total loop time supports experiment scheduling and GPU budgeting.

可训练参数Trainable parameters

参数量由训练日志与检查点张量形状交叉核对。OpenWAM 共 12.406B 参数，其中 6.021B 参与更新；π0.5 共 3.617B，其中 3.353B 参与更新。OpenWAM 的可训练参数约为 π0.5 的 1.80 倍，因此它在前两组对比中的速度优势需要从计算路径解释。

Training logs and checkpoint tensor shapes agree on the counts. OpenWAM stores 12.406B parameters, of which 6.021B are trainable; π0.5 stores 3.617B, with 3.353B trainable. OpenWAM has approximately 1.80× as many trainable parameters, so its speed advantage over the first two π0.5 configurations must be understood through the computation performed.

冻结的 VAE 与 T5 在 OpenWAM 每个训练批次中承担前向编码，参数梯度计算与 AdamW 更新集中在视频 DiT、动作 DiT 和状态投影。π0.5 的全参配置同时更新视觉、语言和动作分支。不同模块的参数承担着不同计算：输入 embedding 用于查表，主干线性层在多个 token 位置上重复运算，注意力还需要处理 token 之间的关系。因此，估算每步计算成本需要结合模块的运算类型、序列长度与前后向执行次数。

OpenWAM runs its frozen VAE and T5 for forward encoding in each training batch, while parameter-gradient computation and AdamW updates are concentrated in the video DiT, action DiT, and state projection. Full π0.5 fine-tuning updates vision, language, and action branches. Parameters serve different computations across modules: input embeddings provide lookup tables, backbone linear layers operate repeatedly across token positions, and attention also processes relationships between tokens. Estimating update cost therefore requires the operation types, sequence lengths, and forward/backward execution counts of each module.

计算配置Compute configuration

首先是进入主干的序列长度。OpenWAM 将三路相机拼成 384×320 的画布，每个样本取 9 个时刻；VAE 在时间上压缩为 3 帧、空间上压缩为 24×20，再按 2×2 latent patch 展开为 360 个视频 token，与 32 个动作 token 交互。π0.5 将每路图像缩放并补边到 224×224，经 14×14 patch 得到每相机 256 个视觉 token：四相机加 200 个文本/状态位置与 50 个动作位置，共 1274 个位置；三相机为 1018 个。虽然网络层数、宽度与条件注意力路径也不同，VAE 对时空序列的压缩确实减少了 OpenWAM 主干需要反复处理的位置数。

First, the backbone sequence lengths differ. OpenWAM packs three cameras into a 384×320 canvas at nine time points. The VAE compresses this to three latent frames of 24×20; 2×2 latent patches produce 360 video tokens interacting with 32 action tokens. π0.5 resizes and pads each camera to 224×224, producing 256 visual tokens through 14×14 patches. Four cameras plus 200 text/state positions and 50 action positions give 1,274 positions; three cameras give 1,018. Layer counts, widths, and conditioning-attention paths also differ, but VAE compression reduces the positions repeatedly processed by the OpenWAM backbone.

其次是微批组织。两组主要 π0.5 对照都要执行 4 次微批前后向，才完成一次有效 batch 32 的更新；OpenWAM 一次处理每卡 8 个样本。当前 FSDP2 实现按模块收集和重新分片参数，微批次数会影响这些操作及梯度通信的执行频次。OpenWAM 开启梯度重计算，以额外前向计算换取激活显存，配合较大的微批；π0.5 的两组主要对照关闭了重计算。重计算的额外开销与更大微批带来的执行和通信变化，需要放在同一次参数更新中一起评估。[9]

Second, the main π0.5 comparisons perform four microbatch forward/backward passes per effective-batch-32 update, while OpenWAM processes eight samples per GPU in one pass. The FSDP2 implementation gathers and reshards parameters by module; microbatch count affects these operations and gradient-communication frequency. OpenWAM enables activation checkpointing, trading extra forward computation for activation memory alongside its larger microbatch. The two main π0.5 comparisons disable checkpointing. The added recomputation cost and the execution and communication changes associated with larger microbatches should be evaluated together over a complete parameter update. [9]

最后是实际数值类型与注意力实现。OpenWAM 检查点全部以 BF16 存储，并开启 BF16 autocast。π0.5 配置为 mixed_precision=none，其检查点采用混合参数存储：约 96.69% 为 BF16，约 3.31% 为 FP32。该版本 π0.5 的联合注意力显式计算注意力矩阵与 softmax，OpenWAM 的对应路径调用 PyTorch SDPA；具体内核由设备、形状和 mask 决定。数值类型影响数据存储与运算，注意力实现影响中间矩阵的处理和显存访问方式，这些选择共同参与每步计算开销的形成。[9]

Finally, actual dtypes and attention implementations matter. OpenWAM stores all checkpoint parameters in BF16 and enables BF16 autocast. π0.5 uses mixed_precision=none with mixed parameter storage: approximately 96.69% BF16 and 3.31% FP32. This π0.5 version explicitly computes the joint attention matrix and softmax; the corresponding OpenWAM path calls PyTorch SDPA, with kernel selection determined by device, shapes, and masks. Dtypes affect storage and arithmetic, while attention implementations affect intermediate-matrix handling and memory access. These choices contribute jointly to update cost. [9]

A subsequent efficiency comparison fixes data, three camera streams, effective batch, and software versions, then varies microbatch/accumulation, checkpointing, and attention implementation separately while recording update time and peak memory. Cross-model comparisons retain suitable input representations and report task success under a shared evaluation protocol alongside accumulated training time, covering both update throughput and task-learning efficiency.
