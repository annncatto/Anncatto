OpenWAM 用固定槽位对齐物理字段，其他算法也需要把机器人数据接入固定宽度的主干。它们对字段含义和投影权重采用了不同约定。补零到 32 维只能保证形状兼容；若原模型前 6 维是另一台机器人的关节，保持这 6 个索引并不等于物理意义一致。下表比较各算法在 AlohaMini 上的适配方式，宽度与权重加载规则对应所用的基座配置。[5]

OpenWAM aligns physical fields through fixed slots. Other algorithms also connect robot data to fixed-width backbones, with different conventions for field meanings and projection weights. Padding to 32 guarantees shape compatibility, but retaining six indices originally used by another robot does not guarantee identical physical meaning. The table describes the adapters and foundation configurations used with AlohaMini, rather than every version of each algorithm. [5]

GR00T 的具身 ID 与动作槽位尤其容易混淆。ID 选择“哪组映射权重”，槽位选择“向量哪一列装什么量”。新机器人的 ID 使用新映射参数，同时仍能复用共享 Transformer。SmolVLA 则保留同样形状的 32 维投影，但新启用的通道并不因此自动获得对应的末端语义。[6–10]

GR00T's embodiment ID and coordinate slots serve different purposes: the ID selects a parameter set, while slots assign quantities to vector columns. A new embodiment can learn fresh mappings while reusing the shared Transformer. SmolVLA retains shape-compatible 32-coordinate projections, but newly used local channels do not automatically inherit matching TCP semantics. [6–10]

这些接口的共同作用是把不同单位、不同数量的机器人字段接入固定宽度的网络主干。OpenWAM-α 进一步规定了通道物理含义，能让“左手位置”在不同数据源间占据一致位置；这种约束是否带来更好的微调结果，仍取决于归一化、参考系、数据覆盖和部署解码是否一致。

All these interfaces connect robot fields of varying units and counts to fixed-width backbones. OpenWAM-α additionally standardizes physical channel meanings, keeping quantities such as left-hand position in consistent locations across sources. Whether that constraint improves fine-tuning also depends on normalization, reference frames, data coverage, and deployment decoding.
