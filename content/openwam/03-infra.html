OpenWAM-Infra: A Modular Infrastructure for World–Action Modeling

The infrastructure separates model composition, training runtime, deployment runtime and evaluation protocol. Architectural changes stay within the model while data interfaces, optimization and robot execution remain comparable.

基础设施由模型组合、训练运行时、部署运行时和评估协议组成。其目的在于让架构变化留在模型内部，让数据接口、优化过程和机器人执行保持可比较。

Composable Model

$$C(\mathcal E,\mathcal S,\mathcal M).$$

$\mathcal E$ specifies the visual representation, $\mathcal S$ the networks processing token streams, and $\mathcal M$ which tokens can read one another. The composition rule $C$ orchestrates execution and interaction. The three module classes jointly specify an architecture. The rule itself has no learned parameters; learned capacity resides in the backbones.

$\mathcal E$ 决定视觉内容如何表示，$\mathcal S$ 决定哪些网络处理这些 Token，$\mathcal M$ 决定 Token 之间能读取哪些信息；组合规则 $C$ 安排这些模块的执行与交互位置。三类模块共同定义一套架构。规则 $C$ 本身不携带可学习参数，参数保存在各个骨干中。

The encoder $\mathcal E$ maps observations into the latent sequence the world stream predicts and is always kept frozen; different encoders capture different information in their latents and in turn induce different world-stream behavior.

编码器 $\mathcal E$ 将观测映射为世界流需要预测的潜在序列，并始终保持冻结；不同编码器在潜变量中保留不同的信息，从而产生不同的世界流行为。

OpenWAM, §3.1

An RGB clip is encoded as $z=\mathcal E(o_{1:T})$. The latent representation space $\mathcal Z$ is the mathematical space of these feature vectors. Its channels, spatial grid and temporal axis determine the numerical description of a scene. Position, appearance, lighting and motion enter through changes in these features; the world stream learns their future evolution.

一段 RGB 视频先被编码为潜变量 $z=\mathcal E(o_{1:T})$。潜在表征空间 $\mathcal Z$ 是这些特征向量所在的数学空间：它的通道、空间网格与时间轴决定模型使用哪些数值描述场景。物体位置、外观、光照和运动会以特征变化的形式进入该空间。世界流随后学习其中的未来变化。

$$o_{1:T}\xrightarrow{\;\mathcal E\;}z\in\mathcal Z,\qquad (z_{t_v},a_{t_a},c)\xrightarrow{\;v_\theta\;}(\hat v_z,\hat v_a).$$

During WAM training, the encoder supplies features and prediction targets; flow matching trains the downstream world and action generators. Freezing it keeps the target representation stable and preserves its interface with the pretrained video backbone. Replacing it changes feature distributions and meanings as well as tensor shapes. Section 4.1.2 therefore reinitializes the generator when isolating encoder effects.

编码器在 WAM 训练中负责提供特征与预测目标，流匹配损失用于训练后面的世界与动作生成网络。冻结编码器使目标表征在训练期间保持稳定，也保留与预训练视频骨干匹配的接口。若直接换成另一编码器，相同张量尺寸并不足以维持原有先验：特征分布与含义也会变化。§4.1.2 因此在比较编码器时重新初始化生成骨干。

A stream is a semantically defined token sequence and processing path; a backbone is the neural network executing that path. Streams may share a backbone or own separate parameters. Stream organization and the noise-to-data flow in flow matching are separate concepts. In the supported Wan and Cosmos generators, video DiTs denoise visual latents; ActionDiT processes action sequences.

Stream 表示具有特定语义的一组 Token 及其处理路径，Backbone 是实际计算这些 Token 的神经网络。两个流可以共享骨干，也可以拥有独立参数。这里的 Stream 描述模型内部的信息组织；流匹配描述从噪声到数据的生成过程。Video DiT 在本文支持的 Wan、Cosmos 视频生成骨干中承担潜变量去噪，ActionDiT 则处理动作时间序列。

Backbones expose input preparation, per-layer execution and final prediction. At bridge layers, execution splits before and after attention: streams emit their own Q, K and V, interact through shared attention, then return to their own residual and FFN paths. Interaction can change without rewriting backbone internals.

各骨干统一暴露输入嵌入、逐层计算、输出预测三个阶段。在桥接层，逐层计算再拆为注意力前后两半：各流先产生自己的 Q、K、V，在共享注意力中交互，再返回各自的残差与 FFN 路径。这样可以改变信息交换方式，同时保留骨干内部的参数结构。

Training Runtime

A sample contains instruction $\ell$, clip $o_{1:T}$, future action chunk $a_{1:H}$, proprioception $q$, and valid-action mask $m$. Language and state form context $c$; the encoder produces visual latents $z$. The streams sample separate noise times $t_v,t_a$, with $t=0$ denoting pure noise and $t=1$ clean data.

一个训练样本由语言指令 $\ell$、视频窗口 $o_{1:T}$、未来动作块 $a_{1:H}$、本体状态 $q$ 和动作有效维度掩码 $m$ 构成。语言与状态形成条件 $c$；编码器产生视频潜变量 $z$。世界流与动作流分别采样噪声水平 $t_v,t_a$，本文统一约定 $t=0$ 为纯噪声，$t=1$ 为干净数据。

$$\begin{aligned}z_{t_v}&=t_vz+(1-t_v)\epsilon_v,&\epsilon_v&\sim\mathcal N(0,I),\\a_{t_a}&=t_aa+(1-t_a)\epsilon_a,&\epsilon_a&\sim\mathcal N(0,I),\\(\hat v_z,\hat v_a)&=v_\theta(z_{t_v},a_{t_a},t_v,t_a,c).\end{aligned}$$

The linear paths have time derivatives $z-\epsilon_v$ and $a-\epsilon_a$, which are the target velocities. Training regresses these velocities at sampled noise states. Generation starts from noise and repeatedly evaluates and integrates the learned fields to obtain visual latents and actions.

线性路径对时间的导数分别为 $z-\epsilon_v$ 与 $a-\epsilon_a$，这两项就是速度场的监督目标。训练在随机噪声状态上回归目标速度；生成时才从噪声出发，多次调用网络并积分得到视频潜变量与动作。

$$\begin{aligned}\mathcal L={}&\lambda_v\,\mathbb E_{t_v,\epsilon_v}\!\left[w(t_v)\left\|\hat v_z-(z-\epsilon_v)\right\|_2^2\right]\\&+\lambda_a\,\mathbb E_{t_a,\epsilon_a}\!\left[w(t_a)\left\|m\odot\bigl(\hat v_a-(a-\epsilon_a)\bigr)\right\|_2^2\right].\end{aligned}$$

$\lambda_v,\lambda_a$ weight the two tasks, $w(t)$ weights noise times, and $m$ selects coordinates labeled for the current embodiment. Clean conditioning frames are excluded from the video loss. Independent sampling covers the joint noise plane, supporting diagonal synchronized paths and paths where one modality leads.

$\lambda_v,\lambda_a$ 控制两个任务的权重，$w(t)$ 调整不同噪声时间的权重，$m$ 限定当前本体有标签的动作坐标。干净条件帧不参与视频预测损失。独立采样 $t_v,t_a$，使训练覆盖二维噪声平面；后续可以沿对角线同步去噪，也可以选择某个模态领先的路径。

  • The runtime supports DeepSpeed ZeRO-1/2, BF16, gradient accumulation and clipping, activation checkpointing and CPU offload.训练运行时支持 DeepSpeed ZeRO-1/2、BF16、梯度累积、裁剪、激活检查点与 CPU offload。
  • Fine-tuning starts a new run from existing weights; resume restores optimizer, scheduler and data position to continue the same run.Fine-tuning 从既有权重开始新的运行；Resume 同时恢复优化器、调度器与数据位置，延续原运行。
  • Checkpoints contain weights, resolved module configuration and action-normalization statistics. Deployment rejects missing statistics to preserve the trained control scale.检查点同时保存权重、完整模块配置与动作归一化统计量。部署缺少统计量时直接报错，避免控制尺度在加载时变化。

Deployment Runtime

Serving mode and denoising schedule are independent choices. Synchronous or asynchronous serving controls overlap between inference and robot execution. Video- or action-leading schedules control progress within a single generation. OpenWAM-α uses synchronous serving and synchronized denoising in its reported evaluations.

执行调度与去噪调度是两个独立维度。同步或异步执行决定推理能否与机器人运动重叠；视频或动作领先决定一次生成内部两个流的去噪进度。OpenWAM-α 的正式评估采用同步执行与同步去噪。

Synchronous serving waits for a fresh chunk when the buffer empties. Asynchronous serving starts background prediction with $d$ buffered actions remaining while the robot continues executing. It skips the stale prefix of the new prediction and adopts the next execution window. The paper uses $H$ for prediction length, $n$ for execution horizon and $d$ for lead threshold, defaulting to $n/2$. Skipping the prefix aligns actions with execution time.

同步执行在缓冲耗尽后等待新动作块。异步执行则在缓冲还剩 $d$ 步时启动后台预测，机器人继续执行旧缓冲；新预测中已经过时的前 $d$ 步被跳过，再采用接下来的执行窗口。论文用 $H$ 表示预测长度、$n$ 表示执行窗口、$d$ 表示提前量，默认 $d=n/2$。跳过过时前缀是为了使动作与当前时间对齐。

$$\begin{aligned}z^{i+1}&=z^i+(t_v^{i+1}-t_v^i)\hat v_z^i,\\a^{i+1}&=a^i+(t_a^{i+1}-t_a^i)\hat v_a^i.\end{aligned}$$

A denoising schedule selects $(t_v^i,t_a^i)$ at each step. Synchronized paths update both streams at equal noise times. Variance shift advances a leading stream toward cleaner states; linear offset initially holds the lagging stream at pure noise. Assigning these curves to video or action selects the leading direction.

去噪调度为每一步指定 $(t_v^i,t_a^i)$。同步路径使两个流在相同噪声时间上共同更新。Variance Shift 让领先流更早到达较干净的状态，Linear Offset 将落后流暂时保持在纯噪声端；将两种曲线分配给视频或动作，就得到不同的领先方向。

$$f_\alpha(s)=\frac{\alpha s}{1+(\alpha-1)s},\qquad h_o(s)=\max\!\left\{\frac{s-o}{1-o},0\right\},\qquad s=i/N.$$

Serving caches language embeddings, skips video decoding, compiles the denoising loop, and reuses stable velocity predictions across nearby steps. Skipping decoding removes the conversion of predicted latents into viewable pixels; the world stream still contributes to action generation.

服务端通过缓存语言嵌入、跳过视频解码、编译去噪循环，以及复用相邻步骤中稳定的速度预测来减少延迟。跳过解码只省去将预测潜变量还原为可观看视频的步骤，世界流仍参与动作生成。

Evaluation Protocol

Benchmarks reach the deployment runtime as thin clients over one persistent WebSocket connection and import nothing from the model or training stack.

各个基准通过一条持久 WebSocket 连接，以轻客户端的形式访问部署运行时，并且不导入模型或训练栈中的任何模块。

OpenWAM, §3.4

A thin client delegates policy computation to the server. A benchmark adapter reads images, instruction and state from the simulator or robot, sends observations, then executes returned actions through its local controller. Model loading, denoising, action buffering and checkpoint-defined normalization stay on the server. “Thin” describes policy responsibilities; simulation and hardware control remain client-side.

轻客户端（thin client）将策略计算交给服务器：基准适配器读取仿真器或机器人的图像、指令与状态，发送观测，收到动作后再调用本地控制接口执行。模型加载、去噪、动作缓冲和检查点定义的归一化在服务器完成。这里的“轻”指策略侧的职责，仿真与硬件控制仍由客户端承担。

A persistent WebSocket reuses one connection across control steps to exchange observations and actions. Clients follow the message protocol without importing Video DiT, ActionDiT or the trainer, so model architectures can change behind the same benchmark interface. The server crops, resizes and tiles views, fills missing cameras, and returns actions in native physical units. Episode reset clears execution state and buffered actions.

持久 WebSocket 在多个控制步复用同一条连接，持续交换观测与动作。客户端只需遵循消息协议，无需导入 Video DiT、ActionDiT 或训练器；模型换成另一种架构，基准端仍使用相同接口。服务器负责裁剪、缩放、拼接相机图像并补齐缺失视角，返回原生物理单位的动作。episode 重置会清除执行状态与旧动作缓冲。

An action head maps final action-stream features to predictions. Cross-embodiment training can use a shared backbone with embodiment-specific heads. OpenWAM instead shares one head, requiring consistent output width and slot semantics. For final action features $X_a$, a shared linear prediction head can be written as:

动作头（action head）将动作流的末层特征映射为预测量。跨本体训练可以采用共享骨干加多个本体专属头；OpenWAM 选择共享一个动作头，因此需要让所有样本具有相同的输出宽度与槽位语义。若动作流特征为 $X_a$，共享线性预测头可写为：

$$X_a\in\mathbb R^{H\times d},\qquad W_{\mathrm{out}}\in\mathbb R^{d\times80},\qquad\hat v_a=X_aW_{\mathrm{out}}+b.$$

The shared mapping predicts 80 coordinates, while validity masks select the supervised and executable channels for each embodiment. Its output $\hat v_a$ is a flow-matching velocity field in action space; integration produces the action chunk.

共享的是从特征到 80 个坐标的映射；不同本体通过有效维度掩码选择各自的监督与执行通道。这里输出的 $\hat v_a$ 是流匹配的动作空间速度场，积分完成后才得到动作块。

A single-dataset model can retain its native action space. Cross-embodiment pretraining uses 80 fixed semantic slots: two 34-D arm blocks containing position (3), rotation representation (6), gripper (1) and dexterous hand (24), plus 12 reserved channels. Shared controls occupy shared coordinates; a validity mask excludes unlabeled slots.

单一数据集可以保留原生动作空间；跨本体预训练采用固定槽位的 80 维空间：左右臂各 34 维，包括末端位置 3 维、旋转表示 6 维、夹爪 1 维与灵巧手 24 维，另有 12 维预留通道。语义相同的控制量映射到同一坐标，没有标签的坐标由有效掩码排除。

$$u=\operatorname{Scatter}_\pi(\operatorname{Norm}(a)),\qquad a=\operatorname{Norm}^{-1}(\operatorname{Gather}_\pi(u)).$$

The index map $\pi$ defines layout and normalization defines scale; proprioception uses the same map. A single arm’s EEF position, 6D rotation and gripper occupy ten valid coordinates. Other-arm, hand and reserved slots can be excluded from that sample’s loss rather than supervised as mandatory zero actions. Gather selects the embodiment’s active coordinates before restoring physical units.

索引映射 $\pi$ 负责坐标布局，归一化负责数值尺度，本体状态使用同一套映射。例如，单臂末端位置、6D 旋转和夹爪共占 10 个有效坐标；另一条臂、灵巧手与预留坐标可以不参与该样本的损失。有效掩码将这些未使用坐标排除，而非把它们作为“必须输出零”的动作标签。执行时 Gather 取回当前本体使用的坐标，再恢复物理单位。
