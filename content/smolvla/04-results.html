120 条基线：已能完成，也仍有边界The 120-episode baseline: successful behavior and remaining limits

下面三段对应左、中、右三个放置位置的成功示例。它们说明已测试的这些位置可以完成任务，并不意味着所有横向距离、朝向和接近距离均已覆盖，也没有足够分母计算位置泛化成功率。每个片段保留原始播放速度，可暂停、拖动时间轴与重复查看。

The next clips show successful left, center, and right placements. They establish success at those tested positions, not coverage of every lateral offset, orientation, or approach distance. There is no trial denominator for a generalization success rate. Clips retain original speed with pause, seeking, and replay controls.

成功过程可以拆成“接近—夹持—抬起—投放”。观察夹爪闭合后物体是否随之抬起，比只看最终机械臂回位更有信息；投放还要确认玩偶确实进入盒子。视频中可见分段调整与停顿，但没有同步 chunk 时间戳，无法给每次停顿标注“模型正在推理”。

Read success as approach, secure grasp, lift, and deposit. Whether the toy rises with the closing gripper is more informative than arm recovery alone; deposit also requires checking the box. Segmented adjustments and pauses are visible, but missing chunk timestamps prevent labeling each pause as inference waiting.

失败片段提示了两个不同的检查方向：一类在抓取阶段未能稳定带起玩偶；另一类发生在物体靠近底盘或机器人向前接近过多时。后者会改变视角、遮挡与右臂的可达空间。现象与这些几何条件同时出现，尚不能区分视觉定位、底盘推进量、夹爪接触或动作块开环执行哪个环节首先偏离。

The failure clips suggest two distinct checks: unsuccessful securing/lifting, and behavior when the toy is close to the base or the robot approaches too far. The latter changes view geometry, occlusion, and arm reachability. Co-occurrence does not identify whether localization, base motion, contact, or open-loop chunk execution first went wrong.

初始姿态：图像相似，控制状态可能不同Initial pose: similar images can hide different control states

{{svmedia:initial-pose-a|initial-pose-b}}

这两段在笔记中标为初始位置变化相关的失败。需要区分的是玩偶位置、底盘位置和关节初始姿态：它们都能改变相机图像，却对应不同的控制问题。同样的物体像素位置，可能来自机器人更近、腕部更低，或者胸部视角变化；同一个关节目标在不同初始姿态下，接近路径也不同。

These clips are annotated as failures associated with changed initial placement. Separate toy position, base position, and joint pose: all affect images but imply different control problems. The same pixel location can arise from different distances or camera poses; an identical joint target can also produce a different approach path from a different start.

SmolVLA 输入状态 token 的意义正在这里：策略应当依据“看到什么”和“自己处于什么状态”共同决定动作。验证时可固定物体与底盘，仅改变复位姿态，再固定姿态、仅改变物体位置。若直接把所有变化统称为位置泛化，失败原因就难以定位。还应确认首次观察采样在复位完成之后，并在新 episode 开始时清空旧动作队列。

This is why state conditioning matters: action should depend on both the scene and the robot’s configuration. Test pose variation with object/base fixed, then object variation with pose fixed. Also check that the first observation follows completed reset and that a new episode clears the previous action queue.

150 条继续训练：退化现象与原因分开Continued training on 150 episodes: separating regression from its cause

{{svmedia:continued-missed-grasp|continued-retreat}}

补充数据后的片段出现了未完成抓取阶段、后退幅度过大的行为，原本任务链条没有稳定保留。旧数据仍参与训练，因此这不是“只看新数据、完全没回放旧数据”的实验。它也不等于已经证明灾难性遗忘：要确认遗忘，需要固定旧场景测试集，证明对同一批旧条件的成功率在继续训练后稳定下降。

The continued-training clips show missed grasp phases and excessive retreat, with the previous task sequence not reliably retained. Old data remained in training, so this is not a new-data-only run. Nor does it establish catastrophic forgetting without repeated before/after evaluation on fixed old conditions.

{{svmedia:continued-success}}

150 条模型也有一次较勉强的成功片段。成功与失败并存，比“完全失去抓取能力”更符合当前材料。可能的变化至少包括数据分布、归一化统计、优化器状态重建、额外训练量与学习率；历史训练的逐模块 dtype 又未完整记录。任何一个因素都需要单独改变、在相同测试条件下比较。

There is also a hesitant successful run with the 150-episode model. Mixed outcomes fit the evidence better than a complete loss of grasping ability. Candidate changes include data distribution, normalization, optimizer restart, extra training, learning rate, and unrecorded runtime dtype details. Each needs a controlled comparison.

尤其是重新计算归一化：对同一个原始动作 $a$，旧、新输入分别为 $(a-\mu_{120})/\sigma_{120}$ 与 $(a-\mu_{150})/\sigma_{150}$。如果投影层从旧检查点继承，而统计量已变，网络所接收和输出的数值坐标也变了。这个变化可以发生在物理示教都正确的情况下，因而不能用“数据质量差”一笔带过。反归一化必须与本次检查点使用的统计量保持成套。

Recomputed normalization changes the coordinates of the same physical action: $(a-\mu_{120})/\sigma_{120}$ versus $(a-\mu_{150})/\sigma_{150}$. Inherited projectors then operate under a changed numerical interface, even if demonstrations are physically correct. This cannot be summarized as poor data quality. Inference must use the statistics paired with the checkpoint.

106 ms 是一次动作块计算的耗时，不是单个控制步耗时，也不是 $1/106\text{ ms}$ 的机器人发送频率。在理想 30 Hz、每次执行 25 步、同步等待 106 ms 的简化模型里，平均动作速率为 $25/(25/30+0.106)\approx26.6$ Hz，与记录的量级接近，但现实的采集、网络和调度耗时仍需分别测量。连续运行 300 s 验证部署能工作，也不等于 300 s 全程任务成功。

106 ms measures one chunk computation, not one control step, and its reciprocal is not the robot’s command rate. A simplified 30 Hz synchronous cycle executing 25 actions then waiting 106 ms gives $25/(25/30+0.106)\approx26.6$ Hz, close in scale to the recorded rate. Acquisition, network, and scheduling still need separate timing. Completing a 300-second deployment run does not establish task success throughout it.
