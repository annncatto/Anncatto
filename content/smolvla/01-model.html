从观察到一段动作From an observation to an action chunk

SmolVLA 是视觉—语言—动作模型（VLA）：输入多路图像、任务指令与机器人状态，输出未来一段连续动作。它由预训练的 SmolVLM2 主干与约 100M 参数的动作专家组成，完整发布模型约为 450M 参数。动作专家不是另一个生成文字的语言模型，而是以 Transformer 为骨架、预测动作空间向量场的网络。SmolVLA 技术介绍。

SmolVLA maps camera images, an instruction, and robot state to a chunk of continuous actions. Its released model has approximately 450M parameters, combining a pretrained SmolVLM2 backbone with an approximately 100M-parameter action expert. The expert is a Transformer that predicts a vector field in action space, rather than another model generating words. SmolVLA technical overview.

把一个动作块记为 $A=[a_0,\ldots,a_{H-1}]\in\mathbb R^{H\times D}$。$H$ 是一次预测的控制步数，$D$ 是单步控制维度。它们与 batch size $B$ 完全不同：$B$ 表示一次训练同时处理多少个样本。一个样本可以包含四张同时刻的相机图像和 50 步未来动作，并不意味着使用了 50 帧历史图像。

Write a chunk as $A=[a_0,\ldots,a_{H-1}]\in\mathbb R^{H\times D}$. Here $H$ is the prediction horizon and $D$ the number of controls per step. Batch size $B$ counts independent training examples. One example can contain four simultaneous camera views and 50 future actions without containing 50 historical images.

例如，本次机器人的真实动作是 18 维；SmolVLA 的发布配置允许补齐到 32 维。模型内部的 $[B,50,32]$ 因而不代表机器人有 32 个自由度：输出还要截回真实维度，并用训练时的统计量反归一化。相机顺序、动作字段顺序和归一化统计都属于模型接口的一部分。发布配置。

This robot has 18 actual action dimensions, while the released SmolVLA configuration pads to 32. An internal shape of $[B,50,32]$ does not describe a 32-DoF robot: outputs must be cropped and unnormalized with the training statistics. Camera order, action-field order, and normalization are part of the policy interface. Released configuration.

追踪 VLM 特征：图像、文字与状态进入哪里Tracing VLM features into the expert

SmolVLM2-500M 的视觉编码器将图像划成 patch，再把相邻特征重排到通道维度，减少视觉 token 数，最后投影到语言模型的 960 维表示空间。以单张 $512\times512$ 图像、$16\times16$ patch、空间压缩因子 4 为例：$32\times32=1024$ 个 patch 变为 $8\times8=64$ 个视觉 token。这里的 4 表示每条空间轴缩小四倍，序列长度总共减少十六倍。SmolVLM2 配置。

SmolVLM2-500M encodes image patches, rearranges neighboring features into channels to reduce token count, and projects them into a 960-dimensional language space. With a $512\times512$ image, $16\times16$ patches, and a spatial compression factor of four, $32\times32=1024$ patches become $8\times8=64$ visual tokens. Both spatial axes shrink fourfold, giving a sixteenfold reduction in sequence length. SmolVLM2 configuration.

{{smolvla:features}}

文字由 tokenizer 转为离散编号，再查 embedding；连续机器人状态则经线性层投影为一个 state token。三者拼成 prefix。四路图像各 64 个 token、文字填充到 48 个位置、一个状态 token 时，prefix 的分配长度为 $P=4\times64+48+1=305$，形状为 $[B,305,960]$。文字中的 padding 位置会被 mask 屏蔽；改变相机数、文本长度、裁图方式或特殊 token 设置，$P$ 也会改变。

Text IDs are embedded, while continuous robot state is linearly projected into one state token. These form the prefix. Four views with 64 tokens each, 48 allocated text positions, and one state token give $P=4\times64+48+1=305$, with shape $[B,305,960]$. Text padding is masked. Different view counts, text lengths, crops, or special-token settings change this length.

原始 SmolVLM2 文本模型有 32 层，SmolVLA 默认保留前 16 层。动作专家也有 16 层，隐藏宽度为 $960\times0.75=720$。它访问的是各层相对应的 VLM key/value 特征，而不只是最后一层的一个汇总向量。常用配置有 5 个 KV heads、每个 head 64 维：第 $\ell$ 层逻辑上的 $K_\ell,V_\ell$ 为 $[B,P,5,64]$；缓存实现也可将其存成 $[B,5,P,64]$。隐藏宽度、注意力投影宽度和缓存的存储顺序不能混为一谈。

SmolVLA retains the first 16 of the original text model’s 32 layers. Its 16-layer action expert has hidden width $960\times0.75=720$. It receives layer-aligned VLM keys and values, rather than a single pooled final vector. With five KV heads of width 64, the logical per-layer shape is $[B,P,5,64]$; a cache implementation may store $[B,5,P,64]$. Hidden width, attention-projection width, and cache layout are different quantities.

prefix 的 attention mask 也有方向：图像和语言不读取后面的状态或动作，状态可以读取前面的视觉语言信息，动作可以读取 prefix。在图里把状态放在视觉语言主干一侧，表示它为动作提供条件，并不表示冻结主干后状态输入就失效。状态投影层仍可以单独训练。embed_prefix / embed_suffix。

The prefix mask is directional: image and language tokens do not read later state or action tokens; state can read preceding visual-language information; actions can read the prefix. A frozen backbone therefore does not make state conditioning ineffective. The state projector may remain trainable. embed_prefix / embed_suffix.

为什么交替使用自注意力与交叉注意力Why alternate self- and cross-attention?

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V.$$

注意力中的 $Q$ 决定“当前动作在查什么”，$K,V$ 决定“去哪里查询、取回什么”。交叉注意力（CA）以动作表示生成 query，读取 VLM 各层的 key/value，把物体、指令和姿态信息带入动作分支；自注意力（SA）则增加动作位置之间的信息交换，使抓取前的接近、夹爪闭合与抬起可以在同一个动作块内协调。

In attention, queries specify what an action representation seeks; keys and values specify where and what it retrieves. Cross-attention reads layerwise VLM information using action queries. Self-attention additionally exchanges information between action positions, helping coordinate approach, gripper closure, and lifting within a chunk.

发布实现的层号从 0 开始：0、2、4…为 SA，1、3、5…为 CA，而不是每一层都完整串联 SA 与 CA 两套模块。SA 层的动作 query 还可以访问 prefix 的 KV，并对动作部分施加因果 mask；CA 层只读取 prefix。这比“SA 完全不看观察”更准确。因果 mask 限制的是动作 token 之间的可见性，不代表推理时逐个输出 50 个动作：整段 noisy actions 仍并行经过网络。注意力实现。

With zero-based layer indices, layers 0, 2, 4… use SA and layers 1, 3, 5… use CA. Each block does not contain two complete attention modules. In the released implementation, SA action queries can also access prefix KV, with a causal mask on the action portion; CA reads the prefix alone. Causal visibility does not mean generating 50 actions serially: the noisy chunk is processed in parallel. Attention implementation.

追踪一个训练 batchTracing one training batch

训练样本给出当前观察 $o$ 和未来示范动作 $A$。模型不必先把噪声迭代成一条完整动作轨迹，才能得到监督信号。它在每个样本上随机抽取一个流时间 $t$ 和一份高斯噪声 $\epsilon$，直接学习这一位置的向量场。这里采用与实现一致的记号：$t=0$ 是示范动作，$t=1$ 是噪声。

A training example contains current observation $o$ and demonstrated future actions $A$. Training does not need to denoise a complete trajectory before obtaining a target. Each example samples a flow time $t$ and Gaussian noise $\epsilon$, then supervises the vector field at that point. We use the implementation’s convention: data at $t=0$, noise at $t=1$.

$$\epsilon\sim\mathcal N(0,I),\qquad x_t=(1-t)A+t\epsilon,\qquad u_t=\frac{\partial x_t}{\partial t}=\epsilon-A.$$
$$\mathcal L(\theta)=\mathbb E_{A,o,t,\epsilon}\left[\left\|v_\theta(x_t,t,o)-(\epsilon-A)\right\|_2^2\right].$$
{{smolvla:batch}}
  • 读取 $B$ 个样本：图像 $[B,N,3,h,w]$、文字 $[B,L]$、状态 $[B,D_s]$ 与未来动作 $[B,H,D]$。归一化后再补齐动作与状态维度。
  • 为每个样本抽取 $t\in\mathbb R^B$ 与 $\epsilon\in\mathbb R^{B\times H\times D}$，构造 noisy actions $x_t$ 和目标 $u_t$。
  • 图像、文字、状态生成 prefix；$x_t$ 与时间 embedding 经 MLP 融合为 $[B,H,720]$ 的 suffix。
  • 动作专家一次前向输出 $v_\theta$，与 $u_t$ 计算逐元素 MSE；训练器再按动作维度、padding mask 和 batch 聚合损失，反向传播并更新可训练参数。
  • Read $B$ examples: images $[B,N,3,h,w]$, text $[B,L]$, state $[B,D_s]$, and future actions $[B,H,D]$. Normalize and pad state/action dimensions.
  • Sample one time per example and matching Gaussian noise. Construct $x_t$ and target $u_t$.
  • Build the prefix; fuse noisy-action and time embeddings through an MLP into a $[B,H,720]$ suffix.
  • Run one expert forward pass and calculate elementwise MSE. The trainer reduces dimensions and masks, backpropagates, and updates trainable parameters.

训练冻结 VLM 时，梯度仍能经过其计算传向可训练的状态投影层；“参数不更新”与“整个前向放在 no_grad 中”并不等价。因此检查冻结策略不能只数模型总参数。上面的正负号则由 $x_t$ 的定义决定：如果改用 $t=1$ 表示干净动作，就必须同时改目标向量场和积分方向。训练 forward 与参数冻结。

Freezing VLM weights does not necessarily remove gradients through VLM operations into a trainable state projector. “Weights do not update” is different from wrapping the entire forward pass in no_grad. The signs above also depend on the time convention: reversing the interpolation requires reversing the target and integration direction together. Training forward and freezing.

追踪一次动作采样Tracing one action-sampling call

推理没有示范动作 $A$。先为最新观察计算一次 prefix，并缓存各层 KV，再从 $x_1\sim\mathcal N(0,I)$ 出发，反复调用动作专家求解常微分方程。采用 $K$ 步Euler 积分：

At inference, demonstration $A$ is unavailable. Compute and cache the observation prefix once, start from $x_1\sim\mathcal N(0,I)$, and repeatedly call the expert to solve an ODE. A $K$-step Euler solver uses:

$$t_k=1-\frac{k}{K},\qquad \Delta t=-\frac1K,\qquad x_{t_{k+1}}=x_{t_k}+\Delta t\,v_\theta(x_{t_k},t_k,o).$$
{{smolvla:sampling}}

默认 $K=10$ 时，视觉编码与 VLM prefix 不是重复执行十遍；重复的是读取固定观察条件、更新 noisy chunk 的动作专家。十步积分得到整段 $H=50$ 个动作，也不意味着机器人必须执行完 50 步才能重看环境。预测长度 $H$、实际执行长度 $n$、积分步数 $K$ 和控制频率 $f$ 是四个独立参数。实际动作还要经过反归一化、字段映射、限幅与发送。

With default $K=10$, image encoding and VLM prefix computation are not repeated ten times. The repeated computation updates the noisy chunk under fixed observation conditioning. Producing $H=50$ actions does not require executing all 50 before observing again. Horizon $H$, executed length $n$, integration steps $K$, and control frequency $f$ are separate settings. Outputs still require unnormalization, field mapping, constraints, and transmission.

SmolVLM：视觉语言能力从哪里来SmolVLM: where the visual-language knowledge comes from

SmolVLM 的预训练知识与机器人动作示教来自两个层次。视觉语言阶段学习文档、图表、问答、图像描述与多图推理；视频阶段加入 LLaVA-Video、Video-STAR、Vript、ShareGPT4Video、Vista、MovieChat、FineVideo 等来源，并保留图像与文本数据。SmolVLA 随后的机器人预训练另用 481 个社区数据集，约 22.9K 条轨迹、10.6M 帧。SmolVLM 数据；SmolVLA 社区数据。

Visual-language knowledge and robot demonstrations enter at different stages. SmolVLM learns documents, charts, question answering, captioning, and multi-image reasoning. Its video stage adds LLaVA-Video, Video-STAR, Vript, ShareGPT4Video, Vista, MovieChat, and FineVideo while retaining image and text examples. SmolVLA’s separate robot pretraining uses 481 community datasets, approximately 22.9K trajectories and 10.6M frames. SmolVLM data; SmolVLA robot data.

异步推理：计算与执行各走一条时间线Asynchronous inference: overlapping computation and execution

同步方案先执行一段动作，再等待下一次预测；异步方案在旧动作队列尚未耗尽时，发送新观察，让计算与执行重叠。对于控制频率 $f$、当前块长度 $H$、剩余队列比例阈值 $g$，触发时的缓冲时间约为 $gH/f$。若端到端预测延迟为 $\ell$，一个直观的避免耗尽条件是：

Synchronous execution finishes a chunk before waiting for the next prediction. Asynchronous execution requests a new chunk while old actions remain. With control frequency $f$, chunk length $H$, and remaining-queue threshold $g$, the available buffer is approximately $gH/f$. For end-to-end latency $\ell$, a simple buffer condition is:

$$T_{\mathrm{buffer}}=\frac{gH}{f}\ \gtrsim\ \ell,\qquad d=\lceil f\ell\rceil,\qquad gH\gtrsim d.$$
{{smolvla:latency}}

这只是确定延迟的时间预算示意。实际延迟包含图像采集与编码、传输、排队、预处理、模型采样和回传；有抖动时还需留余量。新块必须对齐到它被执行的时刻：已经过去的前 $d$ 步不能再从头执行。否则即使 GPU 吞吐率足够，控制也会滞后。更频繁发送近乎相同的观察，还可能不断用相似动作覆盖队列，拖慢进展。SmolVLA 异步队列机制。

This is a deterministic timing illustration. Real latency includes acquisition, encoding, communication, queuing, preprocessing, sampling, and return transfer, with extra margin for jitter. New chunks need execution-time alignment: their already elapsed first $d$ steps cannot simply be replayed. Repeated near-identical observations can also keep replacing a queue with similar plans and impede progress. SmolVLA asynchronous queues.

SmolVLA 的实机结果中，指定计时任务平均用时从 13.75 s 降到 9.70 s，但另一组任务的平均得分从同步 78.3% 变为异步 73.3%（§4.6）。时间收益与任务得分不是同一个指标，不能概括为“异步全面更好”。更进一步，RTC 在生成下一段动作时约束即将执行的前缀，再补全后续动作，处理的不只是等待，也包括新旧动作块不一致。Real-Time Execution of Action Chunking Flow Policies。

SmolVLA’s timed task improves from 13.75 s to 9.70 s on average, while a separate task-score comparison changes from 78.3% synchronously to 73.3% asynchronously (§4.6). Speed and task score are different outcomes. RTC goes further by constraining the soon-to-execute action prefix while completing the rest, addressing chunk inconsistency as well as waiting. Real-Time Execution of Action Chunking Flow Policies.

因此，视频里的停顿至少有三类候选来源：队列真的耗尽、块交接不连续，或者策略本身预测了保持/犹豫动作。前两类要靠时间戳与 chunk 记录定位，第三类才更直接涉及示教分布与模型预测。π0.5 同样可以同步执行，也同样可能在块边界停顿；它并不因模型更大就天然解决实时控制。RTC 的同步执行与交接分析。

A visible pause may reflect queue exhaustion, inconsistent chunk transitions, or a policy predicting a hold. The first two require timing and chunk logs; the third more directly concerns behavior prediction. π0.5 can also run synchronously and pause at boundaries. Larger scale alone does not solve real-time execution. RTC analysis of synchronous execution and transitions.
