浮点表示Floating-point representation

数值类型规定张量元素的编码方式、位宽和可表示范围。机器人学习中，图像像素、文本编号、注意力掩码、网络权重和连续动作使用不同类型：整数用于离散编号，布尔值用于逻辑选择，浮点数用于连续量及可微计算。FP32、FP16 和 BF16 是三种浮点格式。

A numerical type defines a tensor element’s encoding, bit width, and representable range. Robot learning uses integers for pixel values and token IDs, booleans for masks, and floating-point values for continuous variables and differentiable computation. FP32, FP16, and BF16 are floating-point formats.

$$x=(-1)^s\left(1+\frac{m}{2^p}\right)2^e\qquad\text{(normal numbers)}.$$

正规浮点数由符号、指数和有效数字组成。$s$ 为符号位，$e$ 为无偏指数，$m$ 为 fraction 编码，$p$ 为 fraction 位数。指数控制动态范围，fraction 位数控制相邻可表示数的间距。零、非正规数、无穷和 NaN 使用单独编码。IEEE 754。

A normal floating-point value consists of sign, exponent, and significand. Here $s$ is the sign bit, $e$ the unbiased exponent, $m$ the fraction encoding, and $p$ its width. Exponent bits determine dynamic range; fraction bits determine spacing. Zero, subnormals, infinity, and NaN have separate encodings. IEEE 754.

BF16 与 FP32 具有相同的指数位数，适合覆盖训练中跨度较大的数值；FP16 使用更多 fraction 位，在同一数量级内提供更细的分辨率。动态范围与分辨率分别决定溢出、下溢和舍入误差的特征。表中十进制范围保留三位有效数字。BF16 格式。

BF16 shares FP32’s exponent width, while FP16 allocates more fraction bits for finer resolution within a magnitude. Dynamic range and resolution determine overflow, underflow, and rounding behavior. Decimal range limits in the table use three significant digits. BF16 format.

训练精度Training precision

训练精度由参数存储、算子计算和更新累计共同定义。FP32 权重配合 BF16 计算，可以降低矩阵运算与激活的成本，同时保留 FP32 更新分辨率。

Training precision comprises parameter storage, operation dtype, and update accumulation. FP32 weights with BF16 computation reduce operation and activation costs while retaining FP32 update resolution.

  • autocast：按算子选择计算类型。适合的矩阵运算使用 BF16/FP16，数值敏感算子按规则保留较高精度；参数的持久存储由模型和优化器配置。
  • FP32 主副本：在 FP32 中累计优化器更新，再生成低精度计算副本。采用 FP32 参数的 PyTorch 方案直接以参数本身承担这一功能。
  • GradScaler：通过缩放损失与反向梯度缓解 FP16 梯度下溢，更新前恢复梯度尺度。梯度裁剪位于 unscale 之后。BF16 的指数范围通常允许省略这一缩放。
  • Autocast: selects operation dtypes. Eligible matrix operations use BF16/FP16, while sensitive operations follow higher-precision rules. Model and optimizer configuration determines persistent storage.
  • FP32 master values: accumulate optimizer updates in FP32 before producing low-precision compute copies. FP32 parameters directly serve this role in the standard PyTorch recipe.
  • GradScaler: scales losses and gradients to address FP16 gradient underflow, then restores the gradient scale before updating. Clip gradients after unscaling. BF16’s exponent range generally permits omitting this step.

更新舍入Update rounding

低精度直接更新需要将优化器产生的增量重新舍入到参数存储格式。对正规 BF16 数，在区间 $[2^e,2^{e+1})$ 内，相邻数间距为 $\operatorname{ULP}=2^{e-7}$。增量小于相应方向的舍入边界时，写回值保持不变。一般位置的边界为半个 ULP，二次幂边界两侧的间距具有不对称性。ULP。

Direct low-precision updates round optimizer increments back to the stored format. Normal BF16 spacing within $[2^e,2^{e+1})$ is $\operatorname{ULP}=2^{e-7}$. An increment below the directional rounding boundary leaves storage unchanged. Away from binade boundaries the threshold is half an ULP; spacing is asymmetric at powers of two. ULP.

$$w_{k+1}=\operatorname{round}_{\mathrm{dtype}}(w_k+\Delta w_k).$$

$0.01$ 的 BF16 表示为 $0.010009765625$，附近间距为 $2^{-14}=6.103515625\times10^{-5}$。固定增量 $-10^{-5}$ 小于半个 ULP，连续写回 BF16 会逐次丢弃增量。FP32 主副本保存累计值，经过多次更新后，低精度计算副本也随之跨过表示边界。

BF16 represents $0.01$ as $0.010009765625$, with nearby spacing $2^{-14}=6.103515625\times10^{-5}$. A fixed decrement of $10^{-5}$ is below half an ULP and is discarded by each direct write. An FP32 master retains accumulation until the low-precision compute copy crosses a representable boundary.

AdamW 根据学习率 $\eta_k$、一阶矩 $\widehat m_k$、二阶矩 $\widehat v_k$ 与权重衰减系数 $\lambda$ 计算增量：

AdamW calculates the increment from learning rate $\eta_k$, first moment $\widehat m_k$, second moment $\widehat v_k$, and weight-decay coefficient $\lambda$:

$$\Delta w_k=-\eta_k\frac{\widehat m_k}{\sqrt{\widehat v_k}+\varepsilon}-\eta_k\lambda w_k.$$

学习率下降会缩小更新尺度。参数采用 BF16 存储时，更多增量落入同一可表示数的舍入区间，降低单步有效更新比例。FP32 累计将权重的更新分辨率与低精度矩阵计算分离，从而保留这些增量。AdamW。

Lower learning rates reduce update scale. Under BF16 storage, more increments fall within the same rounding interval, reducing the effective update proportion. FP32 accumulation separates weight-update resolution from low-precision matrix computation and retains those increments. AdamW.

混合精度实现Mixed-precision implementation

AlohaMini 的默认 SmolVLA 训练采用 BF16 autocast，参数存储设置为 preserve：VLM 与动作专家沿用构造时的类型，外部投影层保留 FP32。AdamW 直接更新这些参数；trainable_dtype=float32 则在优化器构造前将可训练参数提升至 FP32。

AlohaMini’s default SmolVLA recipe uses BF16 autocast with preserve storage: VLM and expert retain their construction dtypes, while external projectors retain FP32. AdamW updates those parameters directly. Setting trainable_dtype=float32 promotes trainable parameters before optimizer construction.

可训练参数在构造优化器之前转换为 FP32；前向计算通过 BF16 autocast 使用混合精度：

Convert trainable parameters to FP32 before constructing the optimizer, then use BF16 autocast for mixed-precision forward computation:

trainable = [p for p in policy.parameters() if p.requires_grad]
for p in trainable:
    p.data = p.data.float()

optimizer = torch.optim.AdamW(trainable, lr=1e-4)
optimizer.zero_grad(set_to_none=True)
with torch.autocast("cuda", dtype=torch.bfloat16):
    loss = policy(batch)[0]
loss.float().backward()
torch.nn.utils.clip_grad_norm_(trainable, 10.0)
optimizer.step()

标准 FP32 AdamW 为每个可训练参数保存权重、梯度和两份矩估计，基础占用为每个参数 16 字节。100M 个参数对应 1.6 GB；450M 个参数对应 7.2 GB。激活、KV 缓存、临时张量和框架运行开销另外计入。类型审计记录各模块参数、梯度、一二阶矩的 dtype，以及优化器单步前后的参数变化比例。

Standard FP32 AdamW stores weights, gradients, and two moments at 16 bytes per trainable parameter: 1.6 GB for 100M parameters and 7.2 GB for 450M. Activations, KV caches, temporary tensors, and runtime overhead add to this amount. A dtype audit records module-level weights, gradients, moments, and the fraction of elements changed by an optimizer step.
