Floating-point representation浮点表示

FP32, FP16 and BF16 trade representable range against spacing between values. Integers encode token IDs and pixels, booleans encode masks, and floating-point tensors carry weights, activations and continuous actions.

FP32、FP16 和 BF16在数值范围与相邻可表示数的间距之间作出不同取舍。整数编码 token ID 与像素，布尔值编码 mask，浮点张量承载权重、激活和连续动作。

$$x=(-1)^s\left(1+\frac{m}{2^p}\right)2^e\qquad\text{(normal numbers)}.$$

For a normal value, $s$ is the sign bit, $e$ the unbiased exponent, $m$ the fraction encoding and $p$ the fraction width. Exponent bits set range; fraction bits set local spacing, or ULP. Zero, subnormals, infinity and NaN have separate encodings.

对正规浮点数，$s$ 为符号位，$e$ 为无偏指数，$m$ 为 fraction 编码，$p$ 为 fraction 位数。指数位决定范围，fraction 位决定局部间距，即 ULP；零、非正规数、无穷和 NaN 使用单独编码。

Type allocation类型分配

Storage dtype determines retained values; compute dtype determines the arithmetic of each operation. A training pipeline can therefore use different types for data, model modules, activations and optimizer state.

存储类型决定保留下来的数值，计算类型决定各算子的运算精度。因此，训练链路的数据、网络模块、激活和优化器状态可以使用不同类型。

Training precision训练精度

Training precision has three components: parameter storage, operator computation and update accumulation. FP32 weights with BF16 autocast retain fine update resolution while reducing eligible matrix-operation and activation costs.

训练精度由参数存储、算子计算和更新累计三部分组成。FP32 权重配合 BF16 autocast，既保留较细的更新分辨率，也降低适用矩阵运算与激活的成本。

Update rounding更新舍入

Every optimizer step writes $w_k+\Delta w_k$ back to the parameter tensor, rounding to its storage dtype. For normal BF16 values in $[2^e,2^{e+1})$, $\operatorname{ULP}=2^{e-7}$; updates below the directional rounding boundary retain the old value.

每次优化器更新都会把 $w_k+\Delta w_k$ 写回参数张量，并按存储 dtype 舍入。对 $[2^e,2^{e+1})$ 内的正规 BF16 数，$\operatorname{ULP}=2^{e-7}$；更新未跨过相应方向的舍入边界时，保留值仍与原值相同。

$$w_{k+1}=\operatorname{round}_{\mathrm{dtype}}(w_k+\Delta w_k).$$

The usual boundary is half an ULP, with asymmetric spacing at powers of two. Checkpoint files record the values already retained by these in-memory updates.

通常的舍入边界为半个 ULP，二次幂边界两侧的间距则不对称。检查点文件记录的是这些内存更新已经保留的数值。

Actual AdamW increments depend on the learning rate $\eta_k$, moment estimates $\widehat m_k,\widehat v_k$ and decay $\lambda$:

实际 AdamW 增量取决于学习率 $\eta_k$、矩估计 $\widehat m_k,\widehat v_k$ 和衰减系数 $\lambda$：

$$\Delta w_k=-\eta_k\frac{\widehat m_k}{\sqrt{\widehat v_k}+\varepsilon}-\eta_k\lambda w_k.$$

As the learning rate falls, more BF16 updates can remain within the same rounding interval. FP32 accumulation retains smaller increments independently of the low-precision compute copy.

学习率下降后，更多 BF16 更新可能停留在同一舍入区间。FP32 累计独立于低精度计算副本，能够保留更小的增量。

Mixed-precision implementation混合精度实现

Promote trainable weights before creating AdamW, then select eligible forward-operation dtypes with autocast:

先提升可训练权重的精度，再创建 AdamW；前向算子的计算类型由 autocast 选择：

trainable = [p for p in policy.parameters() if p.requires_grad]
for p in trainable:
    p.data = p.data.float()

optimizer = torch.optim.AdamW(trainable, lr=1e-4)
optimizer.zero_grad(set_to_none=True)
with torch.autocast("cuda", dtype=torch.bfloat16):
    loss = policy(batch)[0]
loss.float().backward()
torch.nn.utils.clip_grad_norm_(trainable, 10.0)
optimizer.step()

FP32 weights, gradients and two Adam moments require 16 bytes per trainable element: 1.6 GB for 100M elements, or 7.2 GB if all 450M elements are trainable. Activations, KV caches, temporary tensors and runtime memory are additional.

FP32 权重、梯度和两份 Adam 矩估计，每个可训练元素共需 16 字节：100M 元素约 1.6 GB；若全部 450M 元素都训练，则约 7.2 GB。激活、KV 缓存、临时张量和运行开销另计。
