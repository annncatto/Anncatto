# 论文网页 PPT 工作流

适用于将论文和长篇阅读笔记整理为研究报告式网页幻灯片。目标是让读者沿着论文的问题、方法与证据理解其核心思想。沿用 Anncatto 网站已有的字体、配色、图片查看器和导航组件。

本流程汇总 OpenWAM 从初版到最终版的整轮修改。当前排版规则以本文件为准；[实现与迭代记录](presentation-articles.md)保留技术细节和历史版本。[实验文章写作流程](experimental-article-workflow.md)继续用于完整实验报告。

## 1. 先恢复论文主线

先读原论文、原始笔记和用户提供的讨论，分别提取论文事实、理解难点与制作要求。讨论中的疑问用于定位需要补充的知识，整理后的正文按技术逻辑推进，同一个概念的解释集中完成。

- 核对论文标题、作者、版本、官方实现、图号与许可证。同名论文、同名项目和不同版本先辨明。
- 写清论文要解决的问题、已有方法的具体限制、提出的方法以及验证它的实验。
- 建立“问题 → 方法或概念 → 机制解释 → 实验设计 → 结果 → 设计选择”的论述链。下一页应当承接上一页尚未展开的对象或问题。
- 以原论文的结构和证据为骨架。介绍工作时尽量忠实压缩、翻译原文；自己的解释用于补足理解架构所必需的知识。
- 通用背景和相关工作的篇幅服从当前主题。相关架构图放在首次需要它的正文位置，说明与本方法的关系。
- 对论文的受控实验，连贯交代前提、改变的变量、比较结果及保留的设计。作者解释、实测结果与补充推导分别标明。

开始编排前形成一句清楚的中心论述，并列出支撑它的核心机制与实验。演示结束时应当能回到这条论述。

## 2. 先做逐页提纲，再制作页面

这类论文报告默认以 **15 页以内**作为编排起点，用户另定页数时遵从要求。压缩时合并重复背景和重复结果，保留核心机制、关键实验与必要解释。

- 第一页是标题页，包含完整论文信息、简短主题说明和合适的概览图。
- 第二页直接交代论文的问题、限制和主要贡献。并列提出的贡献使用并列版式，展示它们的关系。
- 后续按论文的研究过程展开。一个框架的组成、训练、部署及评测应当能被识别为同一组内容。
- 每页有明确的论述任务：解释一个机制、比较一组设计，或呈现一项实验及其结论。复杂架构可以连续拆成几页，但保留整体位置与上下文。
- 需要比较的对象同页并列，例如不同架构、信息流方向、预训练条件或 ID/OOD；坐标、单位、训练条件与评测口径对应。
- 在整篇层面均衡信息密度。充分解释图中的机制，利用有效展示面积，同时保留图文间必要的间距。遇到空白先检查论述是否缺环节、主图是否过小、版式是否失衡。

逐页提纲至少记录以下项目：

| 项目 | 要写清的内容 |
| --- | --- |
| 页面任务 | 本页解释的具体对象和要让读者获得的认识 |
| 来源 | 原文章节、图号、表格或官方代码位置 |
| 主图 | 原图、必要局部或拆解图，以及本页重点 |
| 说明 | 输入、模块、输出、变量、实验前提或结果解释 |
| 比较关系 | 哪些内容必须同页对照，哪些条件保持一致 |
| 承接 | 上一页提供什么前提，本页如何引出下一页 |

## 3. 建立来源与内容覆盖表

来源清单放在开发文档中，正文保留读者需要的引用。

- 将每项核心贡献、机制、关键实验、限制和原图映射到正文页面；标明哪些内容在正文展开，哪些由完整文章或原图索引补充。
- 核心架构与关键证据要在页面主体中清楚展示。只提供一个原图链接，不能算作已经解释该机制。
- 保留高分辨率原始资产、图号、来源和许可证。页面可以放大完整面板或去除外白边，完整原图仍可打开。
- 用户要求包括全部原图时，提供完整索引并核对总数与图号。正文优先安排有叙事作用的大图，索引用于查阅其余原图。
- 并用论文图、表、正文或代码时核对其协议与数值。源文存在矛盾时保留原始证据，在内部记录差异，正文采用有依据、范围明确的表述。
- 补充研究只围绕当前机制展开，使用原论文或官方实现，并区分所引用模型的版本与配置。

## 4. 写出能独立读懂的图文

每页需要足够的解释，让读者理解图中的关系。架构图上的模块名应当落实到计算和信息流。

- 明确“谁的输入、训练目标与输出”。说明哪些是观测、条件、标签、噪声、网络预测及最终动作。
- 用同一组符号解释图与公式，在本页给出关键维度、变量和适用条件。特别区分通道数、token 数、隐藏宽度、噪声时间与物理控制时间。
- 训练过程、采样过程和执行过程各自解释完整，再说明它们的连接方式。
- 大标题简短概括本页主题，可以适度改写论文节名。原文章节标题通过来源链接保留，避免用对话式疑问、制作安排或“能说明什么”作为标题。
- 使用加粗突出关键对象、区别和结果。并列事项用短分点；较长的因果解释使用连贯段落。
- 需要突出原文重点时，使用简短引文和相邻译文，再补必要解释；控制引文长度，保留原意、限定条件及来源。
- 引用、图注和摘要都只写读者需要的技术信息。交付前全文检索提示词、AI 历史对话、编辑决定、图片数量制作清单及重复播放提示。
- 首页摘要概括论文主题与贡献。正文和首页预览都要复查。

## 5. 沿用当前标题区与导航样式

正文页使用同一套公共样式，不逐页另调字号和标题位置。

| 组件 | 当前规则 |
| --- | --- |
| 大标题 | 左侧、较大字号；概括本页主题，保留已有正确标题 |
| 章节名与阶段目录 | 位于大标题旁，同一行、同一字号；两者都使用正文级字号 |
| 标题对齐 | **目录行底边与大标题块底边在同一水平线**；英文标题换行时也检查 |
| 原文标题与节号 | 可点击的浅灰来源标注，紧贴在目录行上方；缩写时保留完整标题与正确链接 |
| 当前阶段 | 使用已有浅色底块标识，其他阶段保持可跳转；章节名和阶段关系清楚 |
| 正文与表格 | 全篇统一，沿用公共响应式字号；重点通过加粗与结构表达 |
| 小字 | 用于来源、图号、图注或工具提示；重要解释保持正文字号 |

窄屏允许目录在自身范围内横向滚动，保持章节名与阶段一行。长英文标题优先正常换行；避免缩小目录或让整页横向溢出。第一、二页等没有章节阶段的页面按其实际任务编排，不强加目录。

## 6. 按展示对象选择版式

### 主图优先

- 原论文大图搭配右侧少量分点，或搭配下方一两行完整说明。架构拆解可以占满主体；多个相关架构可以在同一页并列比较。
- 给核心原图明确的展示空间或最小可读高度，避免它只得到其他模块排完后的剩余空间。
- 普通窗口和全屏分别检查主图的实际显示尺寸。`object-fit: contain` 可能产生留白，图片元素的宽高不等于图像实际绘制区域。
- 图注和查看按钮属于辅助行，不能参与主体图文的错误对齐。

### 共用网格，统一对齐基准

- 多列中的同级模块共用网格行，统一上沿、下沿及间距。避免每列各自使用独立的纵向分配，把对应内容推到不同高度。
- 图文对照需要中心对齐时，以**实际图像展示区域的垂直中心**对齐右侧文字模块，排除图注行的影响。
- 同级结果卡片优先共用行；各模块允许内容长度不同，但不通过额外空段或手动偏移制造对齐。
- 对齐既检查元素边界，也检查截图中的视觉关系。图片外白边、字体行高和 SVG 留白都可能造成看起来错位。

### 线框、分隔与结论

- 用细线框区分独立概念或补充内容，用虚线区分同等重要的并列论述；框本身要承担分组作用。
- 箭头用于表达明确的传递、依赖或推导关系；并列且独立的对象直接并列展示。
- 只在有重要发现或设计判断时设置结论色块，文字给出有价值的结论。实验操作和阅读提示放在正文。
- 两段独立结论使用两个紧邻色块；沿用网站蓝、绿、灰配色，当前窄间隙为 6px。不要把每一页都套成固定的底部总结。

### 公式层级

- 直接定义本方法、损失或采样规则的核心公式，给出必要的展示面积、符号与解释。
- **只承担背景作用的常规公式缩小到正文级或略高，必要时改为行内公式**，例如常规 attention；把面积留给架构图。
- 公式、正文和原图的字号分别按用途确定。遇到拥挤，先删重复内容、收紧间距或重组版式，保留重要正文与目录的可读字号。

## 7. 单独检查图片、框与箭头

逐页检查容器内部的关系，同时检查整页边界。

- 标签在模块内居中并有足够内边距；中英文长标签分别检查换行和边界。
- 连线从正确的来源指向读取者或计算结果，方向与公式、掩码和正文一致。
- 箭头沿模块之间的空隙或外侧通道布置。路径、箭头头部和标签均不能穿过模块、文字或其他图注。
- 共用上下文送入多个模块时，分别画清连接；分支路径不能从模块内部错误起始。
- 明确完整架构与局部拆解的对应关系，保留共享与独立的模块、投影、参数及残差路径。
- SVG 视口裁切设置明确的 `clipPath`，检查宽高比变化后的留白区，避免相邻面板泄漏、图像压住线框或裁掉必要标注。
- 裁切原图保留准确的面板编号和完整原图入口。新绘图沿用网站原生 SVG／HTML 风格，图注直接解释内容。

## 8. 先证明交互的意义，再添加动画

每个交互先写清三件事：**用户改变哪个变量、图上哪种关系随之变化、这能帮助理解哪项机制或结果**。无法说明时采用静态图。

- 先核对状态规则或计算公式，再实现动画。选择项要改变对应的连接、可见性、时间路径或计算结果。
- 定义状态表逐项检查，避免选择不同选项却展示同一效果。若科学上确实等价，解释等价范围，保留真正不同的关系。
- 注意力掩码应检查全部受控方向；单独选择一个读取者可能掩盖另一方向的差别。
- 运动点只有在表示真实允许的信息通路或正确的时间演化时才使用。保持实验测量值固定，不能把动画当作模型仿真或新实验。
- 动画按需触发、有限播放；切页、切后台或改变选项时停止旧动画。状态切换不应遗留上一状态的路径或粒子。
- 核心文字、节点和证据默认可见。步骤演示可以辅助理解，分享链接、打印和完整阅读状态都能看到完整解释。
- 检查 `prefers-reduced-motion`、暂停／重置、键盘操作和静态回退。

阅读进度等网站动效与技术演示分别处理。猫头跟随表示当前页位置，可以保留轻微移动；它不承担论文中的科学含义。

## 9. 保留完整的网页阅读能力

- 保留超链接、页锚点、章节目录、原图索引和全文入口；合并页面时兼容原锚点。
- 放大查看图片和 SVG 后，关闭按钮、Escape、焦点与滚动恢复均正常。
- 方向键、空格、PageUp／PageDown、Home／End及目录跳转行为一致，不影响图内控件操作。
- 沿用网站通用的首页入口和阅读组件，不在每篇文章重复实现。
- PPT 进度条保持**通栏贴底、3px 细线**，每格对应一页；猫头随当前页移动，经过文字和按钮时避让。
- 页脚保持紧凑，页码与翻页按钮同一控制行，翻页按钮位于右下角。不能为猫头在全宽范围内额外加一条控制行。
- 检查首尾页、长距离跳转、连续翻页和窗口缩放；以实际文字与按钮作为避让对象，避免把整块空白布局容器当成障碍。
- 窄屏允许正文纵向滚动，但整页无横向溢出；检查浮动元素是否覆盖滚动内容。打印和禁用 JavaScript 时保持可读。

## 10. 完成两轮复查，再交付

第一轮按论文逻辑连续阅读：核心思想是否完整、机制是否解释到位、实验是否确实支撑判断、下一页是否自然出现。第二轮按页面逐项检查：排版、实际图像尺寸、重叠与交互。

| 检查范围 | 通过条件 |
| --- | --- |
| 内容与来源 | 论文身份正确；核心架构、实验与限制已覆盖；原图完整可查；补充解释有明确用途 |
| 标题区 | 大标题与目录底边对齐；章节名与阶段同字号同一行；来源在其上方且可跳转 |
| 信息密度 | 图与解释都充分可读；比较同页并列；没有无效空白、重复结论或凑页背景 |
| 图与公式 | 主图足够大；常规公式不抢占面积；标签、框、路径和箭头无重叠 |
| 多列版式 | 对应模块共用行；图文按预定中心或边界对齐；图注不造成偏移 |
| 动画 | 状态差异正确、作用清楚、数值可信；切页停止；减弱动态效果可用 |
| 阅读交互 | 图片放大可退出；来源、目录、全文、深链接和键盘操作正常 |
| 页脚 | 通栏细线、猫头跟随、单行控件和右下角按钮同时成立，无遮挡 |
| 双语与屏幕 | 中英文各自逐页检查，长标题和长标签不溢出；实际进入／退出全屏 |
| 公开文字 | 正文、图注、首页摘要和英文版本无提示词、AI 历史对话与制作记录 |

以 1440×900 为常规检查尺寸，并覆盖 1280×800、1366×768、1920×1080，以及 320、390、768px 窄屏。既检查页面 `scrollHeight`，也测量标题、目录、结论栏、卡片内部文字和 SVG 的实际边界。对共享布局的修改，复查所有使用该组件的页面。

构建与内部链接检查按仓库现有流程执行。交互计算改变时做针对性验证；纯文字、文档或低影响样式修正，不重复运行无关测试。浏览器检查包含视觉截图和实际操作，不能仅依赖边界数字。

依据当前会话的发布授权处理上线；发布前形成具体可检查结果。文章维护发布仅包含相关文章与公共组件，隔离未发布的主页实验。上线后核对部署结果、线上页面和关键资产，确认实际版本已更新。

## 初版到最终版的可复用经验

| 返工原因 | 固定下来的做法 |
| --- | --- |
| 初稿成为通用知识讲义，论文自身的结构和研究问题变弱 | 先建立原论文的论述链；背景知识只在理解当前机制时补入 |
| 为压页数删掉解释，或为填空白重复分数与口号 | 以机制和证据提高密度，保持各页均衡，先重组再压缩 |
| 原图数量齐全，关键图却太小 | 核心原图直接占据主体；完整索引用于查阅，不能替代正文解释 |
| 通用公式比架构更显眼 | 按公式的实际用途分级，缩小常规公式，把空间让给结构图 |
| 两列分别排满后，同级内容高低错开 | 共享网格行；图文中心对齐时排除图注和画布留白 |
| 页面没溢出，但图、文字、线框或箭头内部相撞 | 增加模块内部边界和路径检查，并逐页看截图 |
| 动画选择变化了，实际信息流没有变化 | 先定义状态和受控方向，再检查每种选择的可见关系与运动路径 |
| 标题、章节名、阶段目录和来源标注过于分散 | 使用统一标题区：左侧大标题，旁侧目录一行，来源置上方，底边对齐 |
| 新增界面元素侵占内容区或遮挡按钮 | 在公共组件中解决布局，检查首尾和过渡帧，保持紧凑控制区 |
| 只修用户指出的一页，同类问题继续出现 | 把修改归入组件规则，全文及双语一并检索和检查 |
