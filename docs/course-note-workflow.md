# 课程笔记整理工作流

适用于将课程笔记、PPT 截图、计算例题和调研材料整理为长篇博客。本流程提炼自《轻量化结构设计》的多轮重构，固定已确认的写作与验证要求；章节安排仍服从具体内容和用户当次要求。

[轻量化实现记录](lightweight-design.md)保存文件、计算与界面实现，[素材覆盖表](lightweight-source-coverage.md)及其 JSON 保存笔记、图片与文章的对应关系。[论文网页 PPT 工作流](presentation-workflow.md)用于演示文稿，[实验文章写作流程](experimental-article-workflow.md)用于实验报告。

## 1. 读全原材料，区分事实与写作要求

- 同时阅读 Markdown 正文、嵌入截图、公式、表格、图注和指定参考笔记。只有图片的笔记也要逐张读取。
- 提取用户强调的定义、关键词、例题、图表和必须保留的章节；对话中的问题用于恢复关注点，提示词和 AI 回答不能直接充当正文。
- 对每张图记录主题、来源、待提取的数据与拟放置的段落。OCR 用于辅助识别，公式、上下标、数值、单位和箭头关系人工核对。
- 原笔记作为输入保留。改写文章和重绘资产存放在博客仓库；来源清单与复核过程保存在开发文档中。
- 建立素材覆盖表，确认关键文字、图表和例题有明确去处；重复素材可以合并，并记录合并关系。

## 2. 先确定论述主线和章节职责

- 遵从用户明确指定的章节结构，再在各章内按概念、机制、推导、例子和工程应用组织。
- 《轻量化结构设计》的既有主线为：导论 → 经典方法 → 集成方法 → 概念设计 → 惯量与质量 → 轻量化指标 → 形状 → 结构效率 → 拓扑优化。它体现从目标、约束到选材、结构和方案验证的递进。
- 每章说明正在解决什么设计问题、需要什么前提、用哪些方法判断，以及如何连接下一章。
- 导论完整说明基本概念，但不挤占后面公式、力学机制和工程分析的篇幅。
- 关键词应当组成有因果关系的论述。例如载荷分析如何进入应力与变形校核，刚度如何影响模态和控制，制造精度如何影响装配与实际运动。
- 为问题归并解释，避免把一问一答拆散到多处，也避免逐个关键词写成彼此无关的词条。

## 3. 定义、要求和适用条件要具体

- 优先保留原材料中准确、完整且已获用户确认的定义。定义应当解释对象本身，避免用泛泛的目标口号替代。
- 写出实际约束，例如刚度、强度、耐久性、振动噪声、被动安全和成本；比较质量、性能或收益时说明载荷、尺寸、寿命、误差及基准。
- 区分设计目标、约束、自由变量和评价指标。材料指数必须与受力方式、约束类型和允许变化的几何量对应。
- 发现原笔记中的概念错误时核对并修正，例如线弹性柔度与刚度的关系、输出端反射惯量的折算方向、特定机器人电机的实际布置。
- 标准、论文结论和产品参数核对原始来源与适用范围。动能表达式、摩擦估算或单一结构初筛不能直接等同于整机安全结论。

## 4. 逐章写出完整解释链

每章先形成可独立阅读的论述，再补充图表与引用。建议顺序为“对象和需求 → 原理或模型 → 计算关系 → 具体设计 → 结果与工程含义”。材料充分时可以合并，避免机械套用小节。

- 标题简短明确，直接概括主题；标题层级统一，全文一个主标题，章节和小节使用相应层级。
- 正文直接说明事实、关系和判断，删除“课程提到”“笔记里写了”“根据之前讨论”等来源叙事。
- 删除没有新增事实的泛泛过渡、同义反复、口语化问答标题和为凑篇幅添加的背景。
- 重要名词首次出现时适量链接 Wiki 或权威解释；相关知识自然接着论述，避免频繁跳转打断阅读。
- 题目与直接引文使用引用样式；Markdown 用 `>`，HTML 用 `blockquote`。真正并列的条件和要点用列表，因果分析保留为连贯段落。
- 用加粗突出定义、关键区别和结果，控制使用密度。图注说明图中对象、条件或数据，制作指令和修改决定留在开发记录。

## 5. 公式推导与工程判断

- 给出模型对象、载荷、支承、目标约束及自由变量，再写质量或性能表达式，消去自由变量，得到可用于比较的指标。
- 定义每个关键符号、单位和方向，保持图、公式、表格及程序一致。推导中的近似和适用条件写在对应步骤。
- 拉杆、梁、板和薄壁管分别处理；固定外径与固定壁厚可得到不同材料指数，不能直接套用同一个比刚度排序。
- 区分杨氏模量和剪切模量、截面二次矩和质量转动惯量、局部应力和整体刚度、固有频率和闭环带宽。
- 数值表格注明材料状态、方向性、单位及取值范围。比强度、比模量与材料指数在同一套单位中计算。
- 例题先完整呈现条件，再推导、代入、比较，最后说明改变约束或非质量要求如何影响选择。
- 静态、动态、疲劳、热和制造指标放在对应设计问题中解释；重要公式用于支持判断，不能只列公式和结论。

## 6. 调研案例要落到具体设计与收益

每个案例核对“设计对象、采用的结构或工艺、作用机制、收益、代价和条件”，再决定篇幅。

- 经典材料、结构和制造方法优先使用与主题相关的大型工程、航空等案例；机器人案例解释质量分布、传动和功能集成。
- 说明具体改变了什么：电机近端布置、截面调整、载荷方向铺层、结构与弹簧共用、传感与关节集成等。
- 收益有可靠数值时给出基准、单位和工况；只有机制证据时说明力学关系，避免补造百分比。
- 电机移位要同时计入传动、支承和其他随动部件；低减速比要连接转矩、转子惯量、摩擦和反向驱动性。
- 各案例围绕自己的关键设计分析，避免重复套用“更轻、更高效、更安全”的理由。
- 优先引用论文、研究机构、官方实现或制造商原始资料，避免从宣传口号反推工程结论。

## 7. 图表：先找可靠原图，再决定重绘

- 课程截图用于恢复信息。重要的 Ashby 图、材料比较、架构或工程图，优先寻找作者、教材或官方高清来源。
- 没有合适原图时，以原生 SVG、HTML 或科学绘图重绘，完整保留节点、数据、坐标、单位、方向和反馈关系。
- 表格完整提取关键字段，保留材料状态、方向、单位和注释；数据存在问题先核实，不悄悄改成更好看的排序。
- 材料图保留坐标定义和原有版权标记；辅助重绘图准确说明其示意性质与来源。
- 曲线与其极值、切线、标注必须来自同一表达式。成本—质量曲线的最低点和边际收益不能各自手工摆放。
- 把公式计算、图形关系与工程含义放在一起。图足够大，标签可读，检查中英文换行以及箭头、文字和线框的内部碰撞。

## 8. 交互与演化图必须有实际依据

- 先说明交互改变哪个变量、计算结果如何变化、帮助理解什么，再决定是否实现。
- 选材、截面、反射惯量和碰撞能量等曲线采用明确模型与单位。用户操作要改变相关计算结果，避免仅改变高亮。
- 拓扑优化展示明确的支承、载荷、网格、体积分数、惩罚和过滤规则；用真实求解得到的迭代状态呈现演化。
- 简支梁的迭代展示同时提供密度或灵敏度场、柔度目标、体积和必要收敛指标。静态阶段、播放和手动选择保持对应。
- 保存生成脚本与结果元数据，验证关键量和物理关系。不能用随意插值或示意动画冒充优化求解。
- 允许暂停、复位、逐步比较和静态阅读；图表放大后必须能退出。

## 9. 全文复读与界面检查

- 逐章连续阅读，检查概念衔接、重复论述、缺失前提、空泛判断以及图与文字是否互相支持。
- 全文检索同类问题。用户指出某个段落冗余、案例失实或标题不清时，检查其他章节是否也有相同模式。
- 原笔记、来源覆盖表与文章逐项对应；重新核对例题、表格、图片和用户强调的关键词。
- 中英文同步修正事实、符号和图注，分别检查字号、表格横向滚动、图内标签和正文溢出。
- 浏览器实际操作图片查看器的关闭按钮与 Escape，确认焦点和滚动恢复；检查文章目录、来源和首页入口。
- 首页入口、查看器和阅读导航等通用功能在公共组件中实现。独立交互工具与文章正文分开维护。
- 工具的真实能力按实现和验证结果说明；网页上能播放参考轨迹，不等于已经验证动力学行走。

## 10. 保存与交付

- 正文采用仓库现有 HTML、双语和章节拼装方式，保留正确锚点与公共样式。
- 开发文档记录来源对应、公式修正、图形生成方式、验证范围和重要限制；公开正文去掉提示词、AI 历史对话和工作记录。
- 按改动运行构建、内部链接检查及必要的计算验证；纯文档或低影响文字调整不重复运行无关测试。
- 发布遵从会话已有授权，文章更新与本地实验工具分开；排除未授权上线的主页和工具改动。
- 发布后核对实际页面和资产。交接时记录分支、路径、验证结果、未完成事项和明确的发布边界。

## 多轮重构形成的固定经验

| 反复出现的问题 | 工作规则 |
| --- | --- |
| 用空泛的最小质量表述替代课程定义 | 保留准确的定义，列出具体约束、自由变量与比较基准 |
| 只读笔记正文，忽略截图中的内容 | 图片、公式、图注和表格同样纳入阅读与覆盖核对 |
| 围绕关键词各写一段，章节彼此脱节 | 先确定设计问题，再按机制、计算和应用组织连续论述 |
| 将 AI 对话、写作要求或修改决定写进正文 | 重新组织技术事实，过程信息只留在开发文档和对话 |
| 调研案例与轻量化主线关系弱，分析重复 | 每例写清具体设计、力学作用、收益和代价 |
| 材料指数脱离几何自由度，概念照抄错误 | 从模型和约束推导，并核对量纲、方向及适用条件 |
| 简支梁演化敷衍，交互没有实际计算意义 | 保存并展示真实求解状态、目标和收敛信息 |
| 图片可放大但无法退出，通用功能逐篇实现 | 使用共享查看器和导航，实际检查关闭、返回与窄屏 |
| 文章更新混入未准备好的独立工具 | 正文、工具和发布范围分别管理，交接明确实际能力 |
