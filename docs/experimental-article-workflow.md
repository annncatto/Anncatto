# 实验文章写作流程

适用于从 Obsidian 草稿、论文、代码、训练记录和实机视频整理成博客文章的工作。原始笔记保留在所属主题目录，文章正文使用仓库已有的 HTML 格式；证据清单与复核记录保存在 `docs/`。

## 写作思路

先确定文章要解释的技术问题，再建立理论与实验之间的联系。算法介绍应当解释实验中真实用到的输入、输出、训练目标和执行方式；实验分析则从具体记录出发，说明现象发生在哪个阶段，再用理论解释相关机制。

一段分析应当完成一个明确任务：描述观察、解释机制、比较配置，或给出证据支持的判断。篇幅由信息决定。标题直接概括内容，正文按逻辑推进，避免用标题代替结论，也避免给每个视频套用同一段理由。

## 1. 读取草稿，确定结构

- 提取必须保留的标题、问题、公式、论文、实验组、视频和图表；将草稿中的指令与事实材料分开。
- 按问题归并理论：例如输入与张量、条件注入、训练与采样、执行时序，各自形成连续论述。算法名称相似时先辨明论文与代码来源。
- 列出章节顺序及每节要回答的问题。沿用用户指定的比较顺序、折叠范围和实验组织方式。
- 原笔记中的对话链接只用来恢复关注点。正文引用原论文、官方实现与实际实验记录。

## 2. 建立证据清单

每组实验至少核对以下信息；缺失且影响判断的项目在对话中询问，独立工作继续推进。

| 类别 | 核对内容 |
| --- | --- |
| 数据 | 数据集版本、示教数、字段顺序、动作单位、相机、统计量、采样频率 |
| 模型 | 策略名称、检查点、初始化、更新范围、参数存储类型、计算类型 |
| 训练 | 本轮与累计步数、batch、学习率、调度、优化器是否恢复、数据采样方式 |
| 执行 | 预测时域、执行窗口、采样步数、同步或异步、控制周期、队列与重置方式 |
| 结果 | 成功次数与总次数、视频对应组、失败阶段、原始轨迹、测量时间基准 |

将论文配置、代码默认值和历史运行配置分别记录。用户确认的实际配置优先于旧报告。参数 dtype、autocast 与优化器状态分别检查，不能用一个 BF16 开关代替整条数值路径。

## 3. 核实理论与公式

- 优先阅读原论文和官方代码。图注标明原图来源；重绘图解释对象本身，不出现制作指令或修改历史。
- 每个核心公式说明变量、维度、单位与适用条件。训练中的随机时间步、去噪迭代和真实控制步分别命名。
- 数值例子标明所用数据。处理器往返测试只说明该计算路径的误差，模型实测输出另用真实记录证明。
- 论文实验交代假设、对照变量、训练范围、评测协议和结果，再说明它支持的结论。
- Wiki 链接附在首次需要解释的术语上；论文与代码链接放在对应论述附近，避免孤立的链接句和过密跳转。

## 4. 逐组组织实验

每组实验采用以下顺序，按材料数量适当合并：

1. 必要的组别与条件说明，详细配置集中放表格。
2. “成功记录：”“失败记录：”等简短分组标签，再放对应视频。
3. 失败视频后紧接一两句现象描述，写清哪个片段、哪个动作、发生了什么。
4. 每组末尾用一两段或更多连续段落分析。先归纳本组结果，再联系条件、模型机制与执行链路，最后给出支持充分的判断。

末尾分析不加“总结与分析：”标签。短描述与末尾分析承担不同作用，避免逐句重复。视频展示失败时，不把尚未检验的原因写入标签；已有明确实验归类时保留原归类，并在分析中说明实际变化。

对比不同模型时，区分视频观感、轨迹统计、推理计时和成功率。后续部署计时注明测试日期，不能默认为前面每段视频的运行条件。成功率必须保留分母；失败案例只按实际记录的阶段解释。

## 5. 分析轨迹与数值

- 每个轨迹章节开头标明模型、训练阶段、评估日期或记录标识、episode 和时间范围；沿用同一记录的后续章节明确关联。
- 原始 action、归一化标签、网络原始输出、后处理指令和状态反馈分别命名。请求前反馈与本次目标的差不直接当作跟踪误差。
- 先验证行数、字段、时间轴和已有报告一致，再计算局部指标。窗口注明边界，带符号分位数与绝对值分位数明确区分。
- 用全量相邻变化检验跳变规律，避免仅凭挑选的几个峰值推断全局特征。刷新间隔与完整往返周期分别计算。
- 将确认的现象、机制解释与待区分的成因分清。正文保留必要的结论边界，不反复列举“还没有做什么”。
- 分析脚本与公开汇总记录可复现的方法、源文件哈希和运行环境；原始数据、私人路径与凭据不随文章上传。

## 6. 图表与阅读体验

- 科学曲线使用标准绘图工具，保存独立 SVG 等清晰资产，沿用网站的蓝、绿、灰配色。
- 交互必须能帮助比较变量、检验计算或理解机制；仅改变高亮的装饰性交互改为静态图。
- 图中节点文字居中、箭头关系明确，变量名与正文一致。图注解释数据、坐标、颜色和来源。
- 视频保留原速与必要控制。同排视频按比例协调高度；不同宽高比不强行铺满相同宽度。
- 手机表格在容器内横向滚动，整页不溢出；放大图可清晰查看，关闭按钮与 Escape 始终有效。

## 7. 编辑检查

按章节连续通读，删去以下内容：

- 草稿提示、AI 对话、编辑历史、“课程提到”“根据笔记”“这里需要补充”等来源叙事。
- “能说明什么”“是什么”等空泛标题，以及“大概”“还需验证”构成的无结论段落。
- 重复的任务介绍、播放提示、免责声明和段末链接句。
- 缺少具体对象的比较、“不是……而是……”式绕述，以及没有数据支持的归因。

检查每段是否增加事实、机制或判断。未增加信息的句子删除。疑问在对话中核实；正文只保留可读、完整的论述。

## 8. 校验与发布

- 在独立文章分支或 worktree 中工作，保留其他未发布功能。
- 运行构建、内部链接和公式检查；按改动范围检查必要的计算，不为纯文字调整新增机械式单元测试。
- 浏览器检查中英文、折叠与目录、视频、表格、图中文字、手机排版和放大退出。
- 提交标题遵循仓库规则；发布后核对部署成功，并验证线上正文和新增资产。
- 本次结论、复现方法和仍需输入的材料记入对应的来源清单，后续更新用新证据替换旧分析。

## 本次经验

| 出现的问题 | 固定的处理方式 |
| --- | --- |
| 将“需要总结与分析”直接写成正文标签 | 视频后写短现象，每组末尾保留自然段落分析 |
| 把归一化零值的算术例子突出成实测原因 | 先检查实际路径与记录，再分开呈现数值例子和真实输出 |
| 曲线未说明来自哪轮实验 | 开头标明模型、检查点阶段、日期与 episode |
| 只凭图上峰值解释周期 | 用逐帧统计确认跳变网格，用频谱区分完整周期 |
| 理论与实验各写各的 | 理论说明后文要使用的变量和机制，分析回应具体失败阶段 |
| 将不确定项反复写进文章 | 在对话中核实；正文只交代影响结论的必要范围 |
| 图表有形式、缺少比较价值 | 保留会改变判断的交互，数据图提供局部放大与明确坐标 |
