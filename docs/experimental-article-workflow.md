# 实验文章写作流程与站点通用模板

适用于从 Obsidian 草稿、论文、代码、训练记录和实机视频整理成博客文章的工作。原始笔记保留在所属主题目录，文章正文使用仓库已有的 HTML 格式；证据清单与复核记录保存在 `docs/`。

## 站点通用实验报告模板（GR00T 2 结构收紧版）

在《SmolVLA & 数值类型》与《OpenWAM & 动作表示》的多轮迭代基础上，吸收《GR00T 2》“结果前置、分点成块、动画/交互解释机制”的论述结构，沉淀为全站实验报告的默认骨架与组件规范。

### 1. 章节主线（结果前置 → 逐项拆解原因）

1. **默认折叠的背景/理论章（`<details class="sv-chapter">`）**：按概念依赖组织，不在理论章之前另加冗长导语；正文首个核心展开区直接进入实验主章（单一 H2）。
2. **任务与核心失败 + 4 卡片 KPI + 总览结论条**：用 1 段说明任务、已有基线表现与核心失败点，随后以 `.sv-kpi-grid`（4 张可视化定量卡片）+ 1 条 `.sv-finding` 总览结论收束全篇判断，避免 KPI 下方再用大段文字重复复述。
3. **实机 / 核心对照结果前置**：紧接基线演示视频之后直接呈现最新真机表（配 `.sv-badge` 状态徽章与 `.sv-tip` 精确悬浮值）、关键帧/核心曲线、2–3 张 `.sv-cards` 对比卡片与选点结论条，让读者先看到“发生了什么”。
4. **逐项原因与机制拆解**：围绕实机差异拆成 2–4 个平级 `<h3>` 机制节（如训练/优化停滞、归一化与数据预处理、条件/表征探针、层间耦合），每节统一采用下方四段式模块，不再把零散审计项铺成长篇流水账。
5. **实验启发与下一轮控制变量方案**：用 `.sv-cards.is-three` 给出 3 条可执行工程改造，再列明下一轮配对实验的固定变量、样本量与计分公式。
6. **折叠实验条件与参考资料**：所有完整超参、探针协议、评估范围收进 `<details class="sv-supplement">` 折叠表，文末使用默认折叠的 `<details id="references">` 有序列表。

### 2. 四段式分析模块（标准 HTML 骨架）

每个机制小节优先按以下四个层次组织，减少长段落与重复铺垫：

```html
<!-- ① 图表或可改变变量的交互/动画组件 -->
<figure class="sv-eval-figure">...</figure>

<!-- ② 2–3 张平行短卡片（每张 1 个短标题 + 1–2 句话：改了什么 → 什么现象 → 说明什么） -->
<div class="sv-cards is-three">
  <div class="sv-card is-alert">
    <span class="sv-card-kicker">...</span>
    <p class="sv-card-title">...</p>
    <div class="bilingual"><p lang="en">...</p><p lang="zh-CN">...</p></div>
  </div>
  ...
</div>

<!-- ③ 单条高亮结论/工程规则（.sv-finding 绿条用于核心结论/工程规则，.is-blue 用于结构/方法启发） -->
<div class="sv-finding">
  <div class="bilingual"><p lang="en"><strong>Takeaway:</strong> ...</p><p lang="zh-CN"><strong>结论：</strong>...</p></div>
</div>

<!-- ④ 完整多位数值与明细折叠（正文保留 1–2 位可读小数，精确值放 .sv-tip 与折叠表） -->
<details class="sv-supplement"><summary>...</summary>...</details>
```

### 3. 结论、命名、配色与动态交互硬约束

- **因果结论必须闭环**：禁止只报测量值而不下判断（例如“属于不同机制”“某层响应最大”“优势来自某样本”必须明确写出：① 具体实验现象与数值量级；② 物理/数值/网络成因；③ 对应的工程动作或设计结论）。
- **自解释命名，禁用不透明代号**：正文中与图例内禁用 `A / B / C`、`模型 1 / 2` 等需读者来回查表的代号，统一改用短而自解释的名称（如 `原 115ep / 微调 10k / 重训 10k / π0.5 21k` 或 `BF16 混合 / FP32 100k`）；关节与代码字段名保留英文（`shoulder_lift`、`lift_axis`、`state_proj`）。
- **克制、精准的陈述句**：禁用设问句（`？`/`?`）、自造词、拟人化或夸张措辞（如“漂移”“偷懒”“彻底学会”），删除写作过程与 AI 对话痕迹；双语文章先写独立可读的英文，再做平行中文。
- **数字精度分层**：正文、卡片与图内标注保留 1–2 位易读小数；多位精确值、样本分母与次要条件通过共享悬浮组件 `src/sv-tooltip.ts`（`.sv-tip` / `.sv-svg-tip`）与 `<details class="sv-supplement">` 承载。
- **原生低饱和配色与双语资产**：所有数据图与内嵌 SVG 严格使用站点色板（墨灰 `#273b43`、弱字 `#61747b`、灰蓝 `#556b73`、主蓝 `#237ab2`、主绿 `#4b9c80`、警示红褐 `#b55d4c`、细线 `#dce9e9`、浅底 `#f8fbfa`）。数据图同时输出 EN/ZH 双语版本（`*.svg` + `*-zh.svg` / `*-zh.webp`），并由同一脚本支持 `--note-output` 同步导出 Obsidian 中文图。
- **有信息增量的动态/交互组件**：优先为“跨层屏蔽巡检”“归一化/数值舍入放大”“队列与延迟”提供能实际切换状态或实时重算数值的交互（`.sv-step-bar` 播放/步进条 + `.sv-live-bars` 同步读数条，遵守 `prefers-reduced-motion` 并保留无 JS 静态可读默认态），拒绝纯装饰性高亮动画。

## 初稿到第二版的重构复盘

这份流程总结的是《SmolVLA & 数值类型》从初稿到第二版的多轮整体重构。主要返工来自论述主线、证据使用与文章语言，最后的视频段落调整属于局部收尾。

### 原笔记中的问题决定主线

初稿重新编排了算法介绍，却偏离了原笔记先比较 SmolVLA 与 π0.5，再展开 SmolVLM 和异步推理的思路。章节虽然覆盖名词，读者仍难以理解这些内容为何出现。重构时先恢复比较对象与问题之间的顺序，再把零散提问归并为连续论述。

写作前需要提炼“为什么关心这个模型、想比较什么、实验暴露什么问题”。章节结构应当服务这些问题。标题采用架构、训练、动作采样、异步推理等简短名称，具体结论放进正文，删除“从观察到一段动作”“曲线能说明什么”等对话式标题。文章只有一个 H1，章节与子节层次一致。

### 每章需要完整的解释链

数值类型初稿将格式介绍、训练设置、舍入现象、论文审计和实验推测分散在不同模块，缺少共同的推理路径。第二版改为“数值类型的含义与使用位置 → 训练中的存储和计算配置 → 论文对照结果 → 舍入与更新机制 → 本次实验的实际设置”。

同一事实只在最合适的位置完整说明。FP32 参数、BF16 autocast、梯度与 AdamW 状态分别列出；ULP 和格式精度用来解释小更新如何消失。论文结果融入相关机制，代码片段只在帮助理解实现时保留。理论应当支持实验判断，实验失败的具体原因仍由本次证据确定。

### 文章语言需要重新组织

初稿保留了大量回答问题的口吻、任务复述、写作安排和证据边界提醒。把这些句子润色得更正式，仍会保留对话结构。重构必须重新组织段落：先写对象与事实，再解释关系，最后给出判断。

删除提示词、AI 历史对话和编辑决定；配置冲突与缺失信息放在对话中核实。避免把“待核实项目”“不能证明什么”反复写入正文。标题概括主题，段落承担分析；一句话没有新增事实、机制或结论时直接删除。

### 原理示例与实测证据必须分开

归一化零值恢复为均值的算术例子曾被过度突出，使读者容易将它理解为底盘微动的已确认成因。重构中核对实际 MEAN_STD 代码、数据统计与停止标签，再用评估记录检查真实目标。原始记录到齐后，以逐帧统计替换仅凭曲线读取的判断。

论文中的 BF16 更新损失也需要先交代实验协议，再用于解释数值机制。它支持一种机制，不直接证明本次机器人失败的原因。代码默认值、运行时 dtype、历史训练设置及论文配置分开核对；用户给出算法目录后，先检查已有代码，避免重复索要本地已经具备的信息。

### 实验组织必须围绕比较关系

初稿的案例、初始位置变化、计时与底盘分析较为散乱。第二版将 120 条 SmolVLA、150 条继续训练、120 条 π0.5 和双玩偶实验连续排列，再集中分析轨迹与底盘速度。每组实验有明确配置、视频现象与组末分析，后续部署计时注明独立测试条件。

视频后先写简短现象，组末再分析阶段、条件变化与模型机制，不以“总结与分析：”开头。避免只换模型名便重复同一套泛化理由。继续训练讨论数据分布、归一化与优化状态变化；抓取失败讨论具体动作阶段；双目标任务讨论顺序执行和旧任务保持。

### 图表需要表达准确关系

初稿部分交互只有高亮变化，注意力图、时序图与图注又混入制作说明。第二版按真实关系重画注意力可见性、延迟与队列、动作数据流，统一文字居中与网站配色，去除外框和重复播放提示。

有意义的交互应当改变可比较的量，例如延迟、缓冲区或数值舍入结果。数据曲线注明记录来源和坐标；25 帧目标切换与约 50 帧完整振荡分别计算。手机排版、视频比例、图表放大退出与目录层级共同属于文章交付质量。首页入口等通用功能在网站层实现。

### 重构后需要整篇复读

逐条修正用户指出的句子会留下相同问题的其他实例。每次结构调整后，应当重新按章节连续阅读，查找重复解释、突兀转场、过时结论、错误跳转和正文中的来源叙事。核实后的配置要同步替换表格、分析、图注和英文版本。完成这一遍编辑，再做构建与浏览器检查。

## 写作思路

先确定文章要解释的技术问题，再建立理论与实验之间的联系。算法介绍应当解释实验中真实用到的输入、输出、训练目标和执行方式；实验分析则从具体记录出发，说明现象发生在哪个阶段，再用理论解释相关机制。

一段分析应当完成一个明确任务：描述观察、解释机制、比较配置，或给出证据支持的判断。篇幅由信息决定。标题直接概括内容，正文按逻辑推进，避免用标题代替结论，也避免给每个视频套用同一段理由。

## 1. 读取草稿，确定结构

- 用户追问用于建立事实与概念的核对清单；正文按对象、机制和实验比较重新组织，不沿提问顺序逐项追加答案。用户要求双语改写时，先完成可独立阅读的英文提纲与正文，再翻译中文，核对术语、条件和结论范围。

- 实验报告外层直接从默认收起的理论章节开始。实验大章按“任务与问题 → 关键发现 → 分组证据与机制 → 实验启发 → 下一轮验证 → 实验条件”组织，完整配置集中章末；理解图表所需的样本范围与指标定义随结果解释。没有额外要求时，不在理论章节之前新增导语。
- 理论按概念依赖组织。先交代读者需要理解的对象，再解释表示、处理和机制，最后连接实验选择。小标题简短概括主题，每节正文自然承接上一节；不要把历史提问拆成彼此孤立的小标题。
- 提取必须保留的标题、问题、公式、论文、实验组、视频和图表；将草稿中的指令与事实材料分开。
- 按问题归并理论：例如输入与张量、条件注入、训练与采样、执行时序，各自形成连续论述。算法名称相似时先辨明论文与代码来源。
- 列出章节顺序及每节要回答的问题。沿用用户指定的比较顺序、折叠范围和实验组织方式。
- 原笔记中的对话链接只用来恢复关注点。正文引用原论文、官方实现与实际实验记录。

## 2. 建立证据清单

每组实验至少核对以下信息；缺失且影响判断的项目在对话中询问，独立工作继续推进。

| 类别 | 核对内容 |
| --- | --- |
| 数据 | 数据集版本、示教数、字段顺序、动作单位、相机、统计量、采样频率 |
| 模型 | 策略名称、检查点、初始化、更新范围、参数存储类型、计算类型 |
| 训练 | 本轮与累计步数、batch、学习率、调度、优化器是否恢复、数据采样方式 |
| 执行 | 预测时域、执行窗口、采样步数、同步或异步、控制周期、队列与重置方式 |
| 结果 | 成功次数与总次数、视频对应组、失败阶段、原始轨迹、测量时间基准 |

将论文配置、代码默认值和历史运行配置分别记录。用户确认的实际配置优先于旧报告。参数 dtype、autocast 与优化器状态分别检查，不能用一个 BF16 开关代替整条数值路径。

## 3. 核实理论与公式

- 优先阅读原论文和官方代码。图注标明原图来源；重绘图解释对象本身，不出现制作指令或修改历史。
- 每个核心公式说明变量、维度、单位与适用条件。训练中的随机时间步、去噪迭代和真实控制步分别命名。
- 数值例子标明所用数据。处理器往返测试只说明该计算路径的误差，模型实测输出另用真实记录证明。
- 区分模型结构、数据预处理和实机诊断。架构部分只说明输入输出接口；实际归一化方式、统计量与示教标签放在实验预处理处。异常分析使用已测量的指令、反馈和数值误差量级，不因存在归一化步骤便将异常归因于它。
- 论文实验交代假设、对照变量、训练范围、评测协议和结果，再说明它支持的结论。
- 通用英文术语、关节名与接口字段名优先沿用原名，如 `shoulder_lift`、`wrist_roll`；首次出现时简要说明动作含义和单位，后文保持一致。统计量同时交代测量对象、计算方式与分母，避免只给抽象译名。
- Wiki 链接附在首次需要解释的术语上；论文与代码链接放在对应论述附近，避免孤立的链接句和过密跳转。
- 文末参考资料统一采用《ACT with CrossEntropyLoss》的紧凑折叠格式：默认收起，使用原生 details/summary、中英文标题和 sources 有序列表；保留 references 锚点，不另设大号二级标题。

## 4. 逐组组织实验

多个对比方案使用自解释短名（如 `微调 10k / 重训 10k / π0.5 21k`，不用 `A/B/C` 抽象代号），在首次需要比较的位置用紧凑表格或短卡片定义改变项、共同条件与步数。正文保留理解当前结果所需的协议，完整配置集中章末折叠表；避免在开头、图前、图注和段末重复定义方案。

每组实验采用以下顺序，按材料数量适当合并：

1. 保留解释比较所需的模型身份与样本范围，详细配置集中放在实验章末表格。
2. “成功记录：”“失败记录：”等简短分组标签，再放对应视频。
3. 失败视频后紧接一两句现象描述，写清哪个片段、哪个动作、发生了什么。
4. 每组末尾用一两段或更多连续段落分析。先归纳本组结果，再联系条件、模型机制与执行链路，最后给出支持充分的判断。

末尾分析不加“总结与分析：”标签。短描述与末尾分析承担不同作用，避免逐句重复。视频展示失败时，不把尚未检验的原因写入标签；已有明确实验归类时保留原归类，并在分析中说明实际变化。

对比不同模型时，区分视频观感、轨迹统计、推理计时和成功率。后续部署计时注明测试日期，不能默认为前面每段视频的运行条件。成功率在对应结果处完整报告一次并保留分母；后续分析不重复强调同一数值。失败案例只按实际记录的阶段解释。

## 5. 分析轨迹与数值

- 正文用模型、示教规模、训练步数、评估日期和实验条件标识记录。运行目录、内部检查点名称、机器地址和审计过程留在来源记录；不把私人实验标识当成读者需要理解的技术概念。
- 每个轨迹章节开头标明模型、训练阶段、评估日期或记录标识、episode 和时间范围；沿用同一记录的后续章节明确关联。
- 原始 action、归一化标签、网络原始输出、后处理指令和状态反馈分别命名。请求前反馈与本次目标的差不直接当作跟踪误差。
- 轨迹图中将 Target 明确标为策略指令，将 Pre-request feedback 标为调用前实测反馈，并注明数据字段和采样顺序。动作队列可能复用此前生成的预测，逐行取动作不代表逐行重新进行网络推理。
- 先验证行数、字段、时间轴和已有报告一致，再计算局部指标。窗口注明边界，带符号分位数与绝对值分位数明确区分。
- 用全量相邻变化检验跳变规律，避免仅凭挑选的几个峰值推断全局特征。刷新间隔与完整往返周期分别计算。
- 将确认的现象、机制解释与待区分的成因分清。正文保留必要的结论边界，不反复列举“还没有做什么”。
- 对抖动、尖峰等曲线现象，追溯原始读数的分布与量化步长，核对换算公式和同一时间段的变化；仅说明“来自反馈”不足以解释曲线形态。区分可以复算的数值机制与尚无独立测量支持的物理成因。
- 后续采集的字段、时间戳、对齐规则和验收条件写入实验协议或开发文档，并在实施时执行；正文围绕已有实验的现象与分析展开，不用“完整诊断还应记录……”替代分析。
- 分析脚本与公开汇总记录可复现的方法、源文件哈希和运行环境；原始数据、私人路径与凭据不随文章上传。

## 6. 图表与阅读体验

- 科学曲线使用标准绘图工具，保存独立 SVG 等清晰资产，沿用网站的蓝、绿、灰配色。
- 网络干预图按真实张量流绘制，标明层组、token 数、信息方向及 Q 行/K-V 列的掩码位置；区分原有可见性与新增屏蔽，画出保留的分支、残差与条件路径。正文分别解释中间表征差异、最终输出差异、比较范围与指标分母。
- 交互必须能帮助比较变量、检验计算或理解机制；仅改变高亮的装饰性交互改为静态图。
- 图中节点文字居中、箭头关系明确，变量名与正文一致。图注解释数据、坐标、颜色和来源。
- 视频保留原速与必要控制。同排视频按比例协调高度；不同宽高比不强行铺满相同宽度。
- 手机表格在容器内横向滚动，整页不溢出；放大图可清晰查看，关闭按钮与 Escape 始终有效。
- 阅读进度与剩余时间统一按当前展开且属于当前语言的内容估算。收起的章节、补充说明和参考资料暂不计入；展开、收起、切换语言及媒体加载导致排版变化时重新计算。到达末尾显示“已到文末”，不将收起的内容标记为已读。

## 7. 编辑检查

优先用肯定句陈述已测结果、适用条件和计算机制；将“没有做到什么”“不能说明什么”改写为明确的比较范围或测量定义。证据边界通过具体条件表达，避免逐段追加否定式声明。

正文充分解释观察、数据关系和机制，不为追求简短把多个推理步骤压缩成一句。每段要增加具体信息；已经说明的条件与边界不反复强调。实验归因只使用核对过的证据，尚未验证的假设改为明确的对照变量与测量项目，不写成现有结果的原因。结尾分析应帮助确定下一组实验或理解算法的实际作用，去掉 AI 对话和回答式表述。

能并列比较的内容优先分点，每段尽量只写一两句话；介绍图表或实验数据时，可用较长段落完成解释。需要展开推理时，将原因、机制和判断分成连续短段，保持解释完整。

按照读者需要作出的判断归类发现。同一个问题下的多条证据放在一起，例如纠偏效果、旧能力保持和训练起点选择；参数精度、归一化等机制用于解释相应问题，不按审计项目各自展开一条主线。

网络拆解本身也是研究发现。围绕同一现象组织输入编码、条件读取、分支信息交换、去噪和优化更新的测量，保留能够定位内部作用环节的结果；路线建议由这些发现和任务结果共同支持。

分别说明参数变化、隐藏表征变化、受控干预和闭环表现测量的对象。固定观测与随机噪声，改变输入条件或屏蔽信息通路，可以量化选定状态下的局部功能作用；注意力分配与参数移动描述内部现象，和干预产生的输出变化并列解释。

Obsidian 的 key finding 同时保留行为与网络层面的核心发现，按它们回答的问题归类。完整配置、曲线与机制解释整合回对应博客文章；原有独有数据和复核材料继续保留在主题附件或实验工作区。

按章节连续通读，删去以下内容：

- 草稿提示、AI 对话、编辑历史、“课程提到”“根据笔记”“这里需要补充”等来源叙事。
- “能说明什么”“是什么”等空泛标题，以及“大概”“还需验证”构成的无结论段落。
- 重复的任务介绍、播放提示、免责声明和段末链接句。
- 缺少具体对象的比较、“不是……而是……”式绕述，以及没有数据支持的归因。

图表承载方案和测量值，图注定义坐标、比较范围与样本，正文解释关键差异及机制。并列配置和结论优先分点，推理保留前因后果；不要用含糊术语或多个省略步骤的长句换取字数减少。

检查每段是否增加事实、机制或判断。未增加信息的句子删除。疑问在对话中核实；正文只保留可读、完整的论述。

## 8. 校验与发布

- 日常博客在主目录的 `main` 上编写、检查、提交和推送，不为文章另建分支或 worktree。保留其他会话的未提交、暂存内容，只提交本任务的文件或片段；用户明确要求本地草稿时按其范围保存。需要隔离的大型未完成工具继续使用独立分支。
- 运行构建、内部链接和公式检查；按改动范围检查必要的计算，不为纯文字调整新增机械式单元测试。
- 浏览器检查中英文、折叠与目录、视频、表格、图中文字、手机排版和放大退出。
- 提交标题遵循仓库规则；发布后核对部署成功，并验证线上正文和新增资产。
- 本次结论、复现方法和仍需输入的材料记入对应的来源清单，后续更新用新证据替换旧分析。

## 关键纠正

| 出现的问题 | 固定的处理方式 |
| --- | --- |
| 重新发明提纲，丢失原笔记的比较顺序 | 先恢复问题主线，再归并理论与实验 |
| 数值章节的模块各说各话 | 按概念、使用位置、训练设置、机制和实测形成解释链 |
| 将写作要求、历史讨论和疑问带入正文 | 在对话中核实，在文章中直接陈述事实与分析 |
| 将“需要总结与分析”直接写成正文标签 | 视频后写短现象，每组末尾保留自然段落分析 |
| 把归一化零值的算术例子突出成实测原因 | 先检查实际路径与记录，再分开呈现数值例子和真实输出 |
| 曲线未说明来自哪轮实验 | 开头标明模型、检查点阶段、日期与 episode |
| 只凭图上峰值解释周期 | 用逐帧统计确认跳变网格，用频谱区分完整周期 |
| 理论与实验各写各的 | 理论说明后文要使用的变量和机制，分析回应具体失败阶段 |
| 将不确定项反复写进文章 | 在对话中核实；正文只交代影响结论的必要范围 |
| 图表有形式、缺少比较价值 | 保留会改变判断的交互，数据图提供局部放大与明确坐标 |
